# Feature Truth Summary

- [md-reader-code-block-strong-decoration-boundary.md](md-reader-code-block-strong-decoration-boundary.md): 记录 fenced code block 在 `Milkdown commonmark + gfm` 中保留原始文本、不会解析行内 `strong` mark 的事实；代码块内 `**文本**` 的可视粗体固定由 ProseMirror decoration 层承担，每个 strong span 必须完整表达 opening marker、content、closing marker 三段，以同时隐藏开闭标记并保持源码不改写。
- [md-reader-topbar-tab-drag-boundary.md](md-reader-topbar-tab-drag-boundary.md): 记录顶部标签栏当前已支持栏内左右拖拽重排、真实顺序必须写回 `session.tabs` 与 `openDocumentPaths`、实施拆分固定为 `tab-order` 纯函数 / `TopBar` 状态机 / `App` 真实提交三层，以及两条长期实现约束：`finishDrag()` 必须先清理本地拖拽态再触发 `onTabReorder`；`buildShiftMap()` 必须按 committed slot 的 `targetSlotLeft - currentLeft` 计算兄弟标签位移，避免多标签跨槽位时重叠。
- [md-reader-session-restore-and-missing-document-self-heal-boundary.md](md-reader-session-restore-and-missing-document-self-heal-boundary.md): 记录本地服务工作区会话恢复、启动占位文案与缺失文档自愈的长期边界：`loadLocalServiceProject()`、`purgeMissingDocumentPath()` 和 `loadDocumentContent()` 在恢复或缺失清理时都必须先同步 `sessionRef.current` 再 `setSession(...)`，`src/App.tsx` 的初始 `statusMessage` 必须保持“正在恢复工作区…”，`src/app/WorkspaceLayout.tsx` 在 bootstrapping 期间固定显示“正在恢复工作区…” / “正在恢复标题导航…”，活动文档外部删除后应自动清理 stale deleted-tab 并回退到有效 tab，`tests/app/app-shell.test.tsx` 与 `tests/app/app-session-restore.test.tsx` 固化占位态、恢复裁剪与运行时自愈回归。
- [md-reader-file-tree-hidden-items-boundary.md](md-reader-file-tree-hidden-items-boundary.md): 记录文件树隐藏与显示项的长期边界：`hiddenPaths` 归入 `WorkspaceProfile.navigation`，`showHiddenItems` 只留在 `App` 会话态并在刷新或切 profile 后重置，文件树采用 source tree / visible tree 分层，`availableDirectoryPaths` 负责目录展开恢复，且隐藏节点的隐藏/解除隐藏动作在 `TopBar` 与 `WorkspaceLayout` 中按显式隐藏与祖先派生隐藏区分处理。
- [md-reader-document-favorites-and-filter-boundary.md](md-reader-document-favorites-and-filter-boundary.md): 记录文档与目录收藏的长期边界：`favoritePaths` 属于 `WorkspaceProfile.navigation` 且可记录文件树节点路径，`showFavoritesOnly` 只属于 `App` 会话态；收藏过滤固定发生在隐藏可见性派生之后、搜索过滤之前，收藏目录保留完整可见子树，刷新/加载会清除不存在的收藏路径，目录路径变更迁移仍未纳入本轮。
- [md-reader-outline-active-heading-subpixel-tolerance.md](md-reader-outline-active-heading-subpixel-tolerance.md): 记录右侧快速导航 active heading 的亚像素容差边界：标题提取链路正常、问题不在 outline 数据源，真实浏览器里需要以 canvas 锚点为基准并在 `src/app/outline-active-heading.ts` 的 active 判定中保留 `0.5px` 容差，配合 `tests/app/outline-active-heading.test.ts` 与 `tests/app/workspace-layout.test.tsx` 固化边界。
- [md-reader-file-tree-document-move-and-path-mutation-boundary.md](md-reader-file-tree-document-move-and-path-mutation-boundary.md): 记录文件树文档移动、重命名、删除、真实移动与同级自由排序的长期边界：`document-path-mutation` 负责同步改写 `session` / `localState` / `profile.navigation`，`manualNodeOrderByParent` 按 profile 持久化显示顺序，`ROOT_ORDER_KEY = '__root__'`，`handleReorderFileTreeNode()` 将 UI 排序写回 `manualNodeOrderByParent`，排序 helper 只负责规范化、投影、同级重排和尾插修正，`normalizeProfile()` 必须保证 `hiddenPaths` / `favoritePaths` 默认数组存在，搜索态与只看收藏态禁拖，目录行与目录按钮共享 drop 入口时必须阻断冒泡避免双重 move 请求，同时把 `rename` / `duplicate` 收敛为同一套行内命名动作态。
- [md-reader-file-tree-document-move-and-path-mutation-boundary.md]: 同时覆盖文件树操作的即时反馈边界：`statusMessage` 负责持久状态文案，`actionToast` 负责新建、复制、重命名、删除、移动等动作的即时回执，目录 drop 命中态应以整行高亮和强调条表达可投放区域，并为重命名/创建副本提供统一的行内编辑体验。
- [md-reader-file-tree-document-move-and-path-mutation-boundary.md]: 有效内部拖拽进入文件树上下 `48px` 边缘时由捕获阶段记录意图并经帧调度连续滚动；每次实际滚动后须重新命中行或尾部刷新落点，且绝不自行提交排序或路径移动。
- [md-reader-document-link-and-deep-link-unimplemented-boundary.md](md-reader-document-link-and-deep-link-unimplemented-boundary.md): 记录只读 Markdown 预览的项目内文档导航、规范分享深链与标题定位边界：内部链接必须经过 `contentRoots` 和文件树校验，普通点击先保存再导航，修饰点击保留规范 URL 的浏览器原生行为，当前文档锚点不保存也不重载，文件树、编辑器链接、旧裸路径与改名移动引用不在范围内。
