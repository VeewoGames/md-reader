# Markdown 与三模式机制

## 概述

`md-reader` 的目标是保留原生 Markdown 的可移植性，同时为不同任务提供合适的操作表面。模式的差异是职责差异，不是不同的数据格式。

## 常规锁定：阅读

常规模式处于锁定状态时，文档通过只读渲染器显示最终预览。它适合完整阅读、标题导航、代码阅读和 Mermaid 图表查看。

## 常规解锁：可视编辑

在常规模式点击“解锁”后，文档进入基于 Milkdown/Crepe 的可视 Markdown 编辑器。它适合标题、段落、列表、引用、强调等已稳定结构化的常见内容。

可视编辑并不承诺把所有 Markdown 结构转成可视控件。对暂未稳定支持、容易因自动重写损失语义或更适合精确修改的内容，应保真为局部源码片段或改用分栏模式。

## 分栏：源码与最终预览

分栏模式固定为两部分：

- 左侧：完整真实 Markdown 源码，可精确修改任意文本。
- 右侧：最终预览，与常规锁定模式承担相同的阅读语义。

因此，分栏是处理复杂表格、frontmatter、原始 HTML、特殊 fenced code block 或需要逐字符修订时的可靠入口。

## Mermaid

标记为 `mermaid` 的 fenced code block 在最终预览中会渲染为图表：

- 常规锁定模式和分栏右侧显示图表。
- 常规解锁的可视编辑可以保留 Mermaid 源码块，不要求显示最终图表。
- 分栏左侧始终显示完整 Mermaid 源码。

图表渲染失败时，只会在该图块显示局部错误并回退显示原始源码，不影响整篇文档。图表缩放和全屏属于临时界面状态，不写入 Markdown 或 Profile。

## 内容变换边界

渲染层可以做经过验证的展示修正，例如隐藏 `synced_block` 包装标签、识别特定异常导出的伪代码围栏；但这些规则必须保留真实 fenced code block 的原样语义。它们是显示兼容策略，不是对源文件的自动格式化授权。
