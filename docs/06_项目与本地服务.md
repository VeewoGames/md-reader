# 项目与本地服务

## 本地服务优先

正式运行路径是本地 Node.js 服务加 Web 前端。服务默认监听 `127.0.0.1:8797`，只面向本机回环地址，不作为局域网或公网服务设计。

启动、检查和停止命令：

```powershell
npm run open
npm run health
npm run stop
```

开发时可直接运行：

```powershell
npm run service:dev
```

## 项目注册与存储

本机项目注册表位于：

```text
%APPDATA%/md-reader/projects.json
```

注册表按 Profile 保存项目列表与活动项目。一个项目包含项目 ID、显示名、根路径、访问方式、内容根目录和权限状态。项目 ID 由目录名和规范化根路径的 SHA-1 短哈希构成，避免同名目录冲突。

项目数组位置就是手工显示顺序。每个 Profile 另有并发版本 `revision`；快照的 `initialized` 区分首次接入与已清空的列表。清空后的 Profile 不会在再次切入时自动接入其他项目。旧登记缺省版本按 0 读取；未知结果协调可保存仅包含 revision 的未初始化占位。

多个新版 bridge 可以共享本机 registry，所有写入在同一个文件事务内排他执行，并用版本检查拒绝过期请求。不能与仍未使用该协议的旧版 bridge 混跑。升级后需在适当时机停止旧实例并重新启动新版服务；仅刷新前端不会更新已经运行的 Node.js 后端。

## 文件扫描与访问范围

默认扫描项目根目录中的 `.md`、`.mdx`，并跳过：

- `.git`
- `node_modules`
- `.md-reader`

文档 API 只接受相对路径，拒绝绝对路径与 `..`。读写、创建、复制、移动和重命名都必须位于项目声明的内容根目录中。

## 主要服务接口

接口用于前端集成与诊断，不建议把它们当成公开远程 API：

- `GET /api/health`：服务健康、模式、端口和项目数量。
- `GET /api/profiles/:profileId/projects`：读取项目列表与活动项目。
- `POST /api/profiles/:profileId/projects/register`：注册项目。
- `POST /api/profiles/:profileId/projects/active`：切换活动项目。
- `POST /api/profiles/:profileId/projects/reorder`：保存完整、无重复的项目 ID 排列。
- `POST /api/profiles/:profileId/projects/unregister`：仅移除登记；当前项移除时同次更新相邻替代项或空 active。
- `POST /api/profiles/:profileId/projects/reconcile`：确认未知提交结果并使旧版本迟到写入失效。
- `GET /api/projects/:projectId/tree`：读取文件树。支持 `mode=prefer-cache|wait|force`：缓存命中返回 `200 ready`，首次索引与强制刷新立即返回 `202` 及 `refreshId`，再以 `wait` 读取同一刷新链终态；刷新失败返回 `503 TREE_REFRESH_FAILED`。
- `GET /api/projects/:projectId/document`：读取文档内容。
- `POST /api/projects/:projectId/document`：写回文档内容。
- `POST /api/projects/:projectId/nodes/document/:action`：创建、复制、移动、重命名或删除文档。

具体请求字段以 `server/bridge-server.mjs` 为实现依据；API 路径、端口或数据格式发生变化时，应同时更新本文档与测试。

清单写入必须带 `expectedRevision`。GET 及成功 mutation 返回 `initialized`、`revision`、`activeProjectId`、`projects`；register 返回 `project` 与 `snapshot`。成功快照供下一次命令直接使用，不应连续复用旧版本。版本冲突为 `409 REGISTRY_CONFLICT`；写入锁等待到期为 `503 REGISTRY_BUSY`，这两类结构化拒绝不会自动重放。

### 遗留锁维护

registry 的事务锁位于同一 runtimeHome 的 `projects.json.lock`。写入通过同目录临时文件和 rename 替换，不先删除正式登记文件。锁不会按年龄或 PID 自动抢占；进程崩溃时可能留下锁，后续列表修改会报告占用。

恢复前先保存可保存的文档，并停止所有使用这一 runtimeHome 的相关实例：受管理实例使用 `npm run stop`，额外手动启动的 bridge 也需分别停止，确认没有写入中的实例。然后查看锁文件的诊断信息，保留需要的证据，只移除对应 `projects.json.lock`，再启动服务。不要删除 `projects.json` 或用户项目目录，也不要在实例仍运行时清锁；PID 与时间只供诊断，不能单独证明锁已失效。

若数据已经保存、仅解锁失败，接口仍返回成功快照和 `lockCleanupWarning`，界面提示维护。此时不要重复提交已经成功的操作。网络中断或响应无法解析则属于结果未知，使用界面的重试确认；需要先完成遗留锁维护时，确认操作也会暂时报占用。

## 离线降级

前端仍保留浏览器目录授权和浏览器存储的降级路径，但它不是正式长期 source of truth。需要可靠读写、项目切换和会话恢复时，应始终通过本地服务启动工作区。

## 文件树缓存与外部变化

服务进程在 `%APPDATA%/md-reader/cache/project-trees/` 持久化完整文件树快照。快照以项目根目录和内容根目录的 fingerprint 识别，并记录 revision、generation、校验时间与 mutation epoch；损坏、越界或身份不符的快照不会被使用。

普通切换优先显示有效快照，过期校验在后台单飞执行；手动 `force` 刷新保证结果不早于点击时刻。节点创建、移动、重命名和删除后缓存会标为 dirty，下一次请求重新校验。外部文件变化不是实时 watcher 同步，需等待下一次校验或使用刷新项目操作。
