# 自动保存与恢复

## 保存原则

`md-reader` 使用自动保存，不使用“是否保存”的确认弹框作为正常编辑流程。输入产生 draft 后，应用会在适当时机提交内容，并在顶部栏显示状态。

常见状态包括：

- 已保存
- 正在保存
- 未保存
- 保存失败

## 离开前刷新

以下操作会先尝试刷新当前脏文档：

- 从常规解锁状态重新锁定。
- 切换阅读/编辑上下文或分栏模式。
- 切换到另一篇文档。
- 服务重启等可能离开当前编辑上下文的操作。

刷新成功后才继续切换；失败时应用留在当前上下文，避免用户在未保存状态下误以为修改已经安全落盘。

## 外部修改冲突

写入时会携带已读取版本的修改时间和内容哈希。若文件在磁盘上已变化且内容不再匹配，服务会报告内容冲突，而不是直接覆盖外部修改。

发生冲突时，应先比较磁盘版本和当前编辑内容，再决定手工合并、重新加载或保留草稿。不要通过反复切换模式绕过冲突提示。

## 会话恢复

应用会保存并恢复：

- 已打开的标签页和活动文档。
- 当前工作区模式与常规锁定状态。
- 标签页滚动位置和阅读进度。
- Profile 中的文件树、大纲和阅读偏好。

恢复时会先等待项目和文档树准备完成。若活动文件已被外部删除，应用会移除失效标签并回退到仍可用的文档，而不是保留失效的活动状态。

## 故障处理建议

1. 看到“保存失败”时，先复制或备份当前内容。
2. 运行 `npm run health` 确认服务可用。
3. 检查目标文件是否被其他程序或 Git 操作改写。
4. 处理冲突后再尝试继续编辑或切换。
