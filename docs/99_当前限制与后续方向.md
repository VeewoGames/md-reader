# 当前限制与后续方向

## 当前限制

- 本产品是本地单用户工作区，不提供多人实时协作、远程同步或服务端版本管理。
- 常规解锁模式不是任意 Markdown / HTML 的全功能所见即所得编辑器；复杂或未稳定支持的结构应通过分栏源码编辑。
- Mermaid 只在最终预览表面渲染；可视编辑中可以显示源码块。
- 项目接入的正式路径依赖本机 Node.js 服务；浏览器目录授权只是降级支持。
- 删除文件不可恢复，应用不代替 Git、备份或回收站策略。
- 当前产品不把样式、布局、数据库块等扩展保存进专有正文格式。

## 已明确的演进方向

- 继续向阅读、可视编辑和分栏预览共享相同 Markdown 语义内核收敛，而不以 DOM 完全一致为目标。
- 在定义完整数据合同后，逐步引入 sidecar 元数据承载高价值、非正文展示状态。
- 扩展可视编辑能力时优先保证 Markdown 保真和可回退到源码，而不是追求全面富文本化。
- 保持本地服务优先的项目访问与保存链路，并持续加强保存失败、冲突恢复和会话恢复的可诊断性。

## 不在近期范围内的方向

- block JSON 作为正文真相层。
- 任意字体、任意字号、多列自由布局等会弱化 Markdown 可移植性的富文本能力。
- 将本地 Markdown 工作区改造成在线文档协作平台。

## 维护规则

当功能、接口或默认行为变化时，应先更新对应的编号文档，再保留或更新 `docs/方案/` 中的历史设计资料。不要把仍在讨论或仅存在于方案中的能力写成“当前已具备”。
