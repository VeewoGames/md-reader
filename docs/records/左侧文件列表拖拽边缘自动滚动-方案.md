# 方案概述：左侧文件列表拖拽边缘自动滚动

## 1. 总体目标和范围

在不改变文件树既有排序、文件移动和落点语义的前提下，让有效文件树拖拽在滚动容器的上下边缘自动连续滚动，支持用户抵达长列表中原本不可见的排序位置或目录。

本方案只处理 `WorkspaceSidebarPane` 内 `.panel__content--tree` 的滚动行为。它不开放跨父级排序，不改变搜索态或只看收藏态的排序禁用规则，也不新增视觉提示。

## 2. 各阶段任务概要

1. **抽取边缘滚动计算**：定义触发带宽、方向和随边缘距离递增的滚动增量，形成可独立测试的纯函数。
2. **接入拖拽会话**：在 `WorkspaceSidebarPane` 维护边缘滚动状态与帧调度，将当前拖拽指针位置映射到文件树面板的 `scrollTop` 变化。
3. **收敛生命周期**：离开触发区、达到上下滚动尽头、放下或取消拖拽时停止调度并清理状态；既有落点高亮与 drop 处理保持原样。
4. **验证交付**：补齐纯函数和组件级测试，并用真实浏览器验证长列表拖拽能够抵达不可见目标。

## 3. 整体结构框架

```text
dragstart / dragover / dragend / drop
                │
                ▼
文件树拖拽会话状态（现有 dragNodePathRef）
                │
                ▼
边缘判定与速度计算（纯函数）
                │
                ▼
requestAnimationFrame 连续滚动
                │
                ▼
fileTreePanelRef.current.scrollTop
                │
                ▼
现有 reorderDropTarget / dropDirectoryPath 反馈与 drop 语义
```

## 4. 设计方案

### 4.1 可测试的边缘滚动计算

在文件树相关 UI 模块附近新增纯计算 helper，输入面板可视区域、当前指针 Y 坐标和触发带宽，输出：

- `direction`：`-1`（上）、`1`（下）或 `0`（停止）；
- `strength`：指针在触发带中靠近边缘的归一化强度；
- `delta`：单帧建议滚动量，随 `strength` 增加而提高。

触发带固定为上、下各约 48px。指针在中间安全区输出 `0`；到达边缘时达到上限速度。具体最小/最大像素数作为实现常量集中管理，由测试锁定比例关系与边界行为，而非把浏览器事件频率当作速度来源。

### 4.2 连续调度与容器边界

`dragover` 只更新当前指针的边缘意图，帧循环负责按最近一次意图更新 `fileTreePanelRef.current.scrollTop`。这样即使原生 `dragover` 的事件频率不稳定，用户停在边缘时仍可平稳连续滚动。

滚动会改变指针下方的行，但浏览器不保证仅因 `scrollTop` 变化再次派发 `dragover`。因此每次实际滚动后，必须使用已保存的 `clientX` / `clientY` 重新命中当前行或列表尾部，并复用现有目标解析，刷新 `reorderDropTarget` 或 `dropDirectoryPath`。这样用户不移动指针时，高亮和最终 `drop` 目标仍会随列表内容移动而更新，而不会停留在滚动前的旧目标。

每一帧都读取实际 `scrollTop` 与可滚动范围：

- 已到顶时不再请求向上滚动；
- 已到底时不再请求向下滚动；
- 滚动未发生时自动停止对应方向的调度，避免空转。

该调度只在 `dragNodePathRef.current` 存在的有效文件树拖拽会话中运行。因此它同时服务同父级排序和文件拖入目录，但不改变它们的目标解析。

### 4.3 生命周期与现有反馈协作

在以下位置统一清除边缘意图并取消待执行帧：

- 指针离开上下触发带；
- `handleTreeNodeDragEnd()`；
- 各类成功 `drop` 的收尾路径；
- 组件卸载。

自动滚动不触碰 `reorderDropTarget`、`dropDirectoryPath`、`resolveRowReorderPositionWithCenterBand()` 或 `onReorderFileTreeNode()` 的职责。滚动仅改变当前可见区域；已有整行落点高亮、插入方向和目录命中反馈继续由原状态机计算。

### 4.4 测试与人工验收

自动化测试分两层：

1. 纯函数覆盖上边缘、下边缘、中间安全区、临界 48px、强度单调递增和速度上限。
2. `WorkspaceLayout` 覆盖有效拖拽时向上/向下滚动、离开边缘停止、`dragend`/`drop` 停止、到达滚动尽头停止；并覆盖“滚动后指针不移动”时落点高亮和最终 `drop` 目标仍会重算到新行或尾部，同时断言既有落点状态不被自动滚动错误清除或篡改。

真实浏览器验收使用超过一屏的文件列表：拖动条目到上、下边缘，确认列表连续滚动、可抵达原本不可见的同级落点或目录；离开边缘与结束拖拽后列表立即停止；过滤态和只看收藏态不产生新的排序能力。

## 5. 影响范围

- 主要实现：`src/app/WorkspaceLayout.tsx`
- 可能新增：文件树边缘滚动 helper（以实现阶段的最小可测位置为准）
- 定向测试：`tests/app/workspace-layout.test.tsx` 及 helper 对应测试
- 不涉及：`src/App.tsx` 的顺序持久化、文件系统 bridge、数据模型或 CSS 视觉规范

## 6. 风险与约束

- 原生拖拽事件频率不稳定，因此不能把每次 `dragover` 直接当作固定滚动步长；需由帧调度持续消费最新意图。
- 测试环境的元素布局与真实浏览器不同，组件测试只能验证状态、滚动调用和清理；真实拖拽体验仍需浏览器验收。
- 自动滚动必须严格绑定文件树容器和有效拖拽会话，不能误影响侧栏外部或其他面板。
