# 左侧文件列表拖拽边缘自动滚动-需求确认记录

## 概述

### 总体目标和范围

为左侧文件列表的既有内部拖拽补充边缘自动滚动，使用户在长列表中拖拽排序或将文件拖入目录时，可以抵达当前不可见的目标。

本需求只辅助现有拖拽过程：不改变同父级排序、文件移动、搜索态、只看收藏态或既有落点的业务语义。

### 各阶段任务概要

1. 提取可测试的边缘判定与滚动增量计算。
2. 将计算接入左侧文件树的有效拖拽会话，并在拖拽结束时彻底清理。
3. 通过定向自动化测试和真实浏览器长列表操作验证交付。

### 整体结构框架

`拖拽指针位置 → 文件列表边缘意图判定 → 连续滚动调度 → 既有落点高亮与拖放处理`

## 已确认需求

1. 自动滚动覆盖全部既有文件树内部拖拽：同父级排序，以及文件拖入目录。
2. 自动滚动只在有效拖拽会话中运行；搜索态和只看收藏态继续遵守当前禁用排序的规则。
3. 文件列表上、下边缘各约 48px 为无视觉触发区。
4. 拖拽指针进入触发区即向对应方向连续滚动；越靠近边缘，滚动速度越快。
5. 指针离开触发区、滚动到达尽头、成功放下或取消拖拽时，自动滚动立即停止。
6. 不新增箭头、提示或其他视觉控件；继续复用现有整行落点高亮和插入方向反馈。

## 明确不做

- 不新增跨父级排序或目录层级改动。
- 不改变真实文件移动和顺序持久化协议。
- 不在搜索态或只看收藏态开放排序能力。
- 不以自动滚动替换既有落点命中、目录拖入或拖放反馈。

## 验收标准

1. 上、下边缘均可触发正确方向的连续滚动，且速度会随靠近边缘而提高。
2. 离开触发区、到达可滚动尽头、拖放成功和拖拽取消均会停止滚动。
3. 自动滚动期间，现有落点高亮和插入方向反馈保持正确。
4. 新增可独立运行的边缘滚动计算测试。
5. `WorkspaceLayout` 定向测试覆盖上滚、下滚、离开边缘、拖拽结束与滚动尽头。
6. 在真实浏览器中，以长列表验证用户可以把条目拖到原本不可见的目标位置或目录。

## 已验证项目事实与限制

- 左侧文件树的滚动容器为 `fileTreePanelRef` 指向的 `.panel__content--tree`，该容器已启用 `overflow-y: auto`。
- 当前拖拽由原生拖拽事件驱动，并以 `dragNodePathRef` 维护会话状态。
- 现有排序仅支持同父级，搜索态和只看收藏态禁止排序。
- 尚未进行真实浏览器拖拽事件频率观察；该限制将由最终浏览器验收补足。

## 已否决选项

- 仅覆盖同父级排序，不覆盖文件拖入目录：不采用。
- 在边缘增加显式箭头或额外提示：不采用。
- 自动滚动改变当前排序、目录移动或过滤态规则：不采用。

## 开放问题

无。后续方案可以在不改变上述体验约束的前提下确定具体帧调度和速度数值。
