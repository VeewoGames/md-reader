# md-reader 文件树自由排序实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 `md-reader` 左侧文件树补齐“同级自由排序并按 profile 固定化”的能力，支持根层和同目录内的文件/文件夹混排拖拽，并在刷新、重启、切换 profile 后稳定恢复。

**Architecture:** 保持 `buildFileTree()` 继续只负责由扫描路径生成基础树；新增一层纯逻辑顺序模块，在 `App.tsx` 中统一应用和持久化。UI 侧仅负责拖拽命中、禁拖边界和排序提交，不承担排序真相或路径修正逻辑。

**Tech Stack:** React 19、TypeScript、Vitest、Testing Library、本地 profile bridge（`server/project-profiles.mjs`）

---

## 方案概述

### 1. 总体目标和范围

本计划覆盖“显示顺序固定化”这一单一子系统，不改变真实文件路径，也不重做已有“拖入文件夹即真实移动”的能力。第一版只支持：

- 根层节点同级自由排序
- 同一父目录直属子项自由排序
- 文件与文件夹同级混排
- 排序结果按 `profile.navigation` 独立持久化
- 搜索 / 只看收藏视图只展示排序后的投影，但不能修改顺序

本计划不包含：

- 跨父级排序拖拽
- 通过排序拖拽改变目录层级
- 项目级共享顺序
- 多选排序

### 2. 各阶段任务概要

阶段一：补齐顺序模型与纯逻辑测试  
预期成果：存在独立的 `file-tree-order` 模块，可完成 normalize、apply、reorder、rename、delete、create 的顺序修正。

阶段二：接入 profile 持久化与 App 构树链路  
预期成果：`App.tsx` 构树后统一应用手工顺序；profile 默认值、读写、老数据兜底一致。

阶段三：接入文件树拖拽排序交互  
预期成果：完整树中可整行拖拽排序，过滤态禁拖，插入位提示明确。

阶段四：接入关联操作与回归测试  
预期成果：新建、删除、重命名、真实移动后，顺序状态仍稳定，前端与纯逻辑回归可跑通。

### 3. 整体结构框架

- `src/workspace/file-tree-order.ts`
  - 排序真相层，纯函数，无 React 依赖
- `src/workspace/file-tree.ts`
  - 继续只负责基础树生成和可见树投影
- `src/workspace/profile-store.ts`
  - 前端 profile 类型与默认值
- `server/project-profiles.mjs`
  - repo profile 默认值与归一化
- `src/workspace/document-path-mutation.ts`
  - 重命名 / 删除 / 真实移动后的排序映射修正
- `src/App.tsx`
  - 构树应用顺序、保存导航、处理节点动作后的顺序更新
- `src/app/WorkspaceLayout.tsx`
  - 排序拖拽交互、禁拖边界、提交回调
- `tests/workspace/*`、`tests/app/*`、`tests/server/*`
  - 纯逻辑、桥接、组件交互和恢复链路回归
