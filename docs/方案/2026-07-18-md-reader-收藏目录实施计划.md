# md-reader 收藏目录实施计划

## 方案概述

### 1. 总体目标和范围

本计划将已批准的收藏目录方案拆成可验证的实施顺序：先建立收藏投影纯函数与刷新修剪合同，再接入目录收藏交互和全量回归。目标是在不改变 Markdown 正文、Profile 作用域或现有过滤顺序的前提下，使可见 Markdown 文件树中的目录可收藏、可在收藏视图展示完整可见子树。

### 2. 各阶段任务概要

1. 建立收藏投影与刷新修剪合同，并锁定单元测试。
2. 在 App 接入 Profile 收藏状态与树刷新修剪。
3. 接入目录收藏交互、空状态与可访问性。
4. 完成跨层回归、类型检查和构建验证。

### 3. 整体结构框架

```text
纯函数合同（收藏投影、有效节点路径收集）
          ↓
App 的 Profile 保存与树刷新修剪
          ↓
WorkspaceLayout 目录收藏入口
          ↓
单元 / 组件 / 集成回归
```

## 前置约束

- 收藏对象限于当前 Markdown 文件树可见的文件与目录；空目录不进入树，不支持收藏。
- 过滤顺序固定为：有序原始树 → 隐藏可见树 → 收藏投影 → 搜索投影。
- `favoritePaths` 继续存放在 `WorkspaceProfile.navigation`，`showFavoritesOnly` 继续为会话态。
- 本轮不新增目录改名、移动、删除或“移动到”交互；应用外路径变更仅在刷新时清理失效收藏。

## 实施任务

### 阶段一：先锁定纯函数合同

1. 在 `src/workspace/file-tree.ts` 重写 `filterFileTreeByFavorites()`。
   - 将收藏路径转换为 `Set`；DFS 同时携带“是否位于收藏目录之下”的上下文。
   - 收藏文件保留自身；收藏目录直接保留当前可见子树；未收藏目录仅在承载收藏后代时克隆并保留。
   - 保持输入不可变与 `VisibleFileTreeNode.meta` 完整。
2. 补充 `tests/workspace/file-tree.test.ts`。
   - 文件收藏、目录收藏、目录内未单独收藏文件、嵌套与重叠收藏、空结果。
   - 隐藏树输入和显示隐藏项输入均覆盖。
完成条件：收藏树投影测试先全部通过，后续 UI 不自行实现收藏匹配。

### 阶段二：App 状态与刷新修剪

1. 在 `src/App.tsx` 统一 `handleToggleFavoritePath()`，让文件和目录共用收藏保存逻辑。
2. 在 Profile 水合与 `refreshProjectTree()` 后收集当前树中有效节点路径，修剪陈旧 `favoritePaths`；只有集合实际变化时保存。
3. 继续保持 `showFavoritesOnly` 的会话态及切换 Profile 后复位行为。
4. 在 `tests/app/app-session-restore.test.tsx` 与 App 层测试覆盖恢复、刷新修剪和 Profile 隔离。

完成条件：文件和目录收藏经由同一保存链路，外部删改后的刷新不会保留失效收藏。

### 阶段三：目录收藏交互

1. 在 `src/app/AppShell.tsx`、`src/app/WorkspaceLayout.tsx` 将 `onToggleFavoriteDocument` 改为 `onToggleFavoritePath`。
2. 在目录行添加与文件行一致的收藏星标。
   - 已收藏常显；星标点击阻止冒泡，不触发目录展开。
   - `aria-label` 精确区分“收藏/取消收藏 <目录名>”。
3. 在目录右键菜单添加收藏/取消收藏；不新增目录改名、移动或删除入口。
4. 将“只看收藏文档”与“当前还没有收藏文档”改为覆盖节点集合的产品文案。
5. 在 `src/index.css` 复用文件行动作的 hover/focus/隐藏样式，避免为目录复制一套互相漂移的样式。
6. 在 `tests/app/workspace-layout.test.tsx` 覆盖目录星标不展开、右键操作、收藏目录 + 搜索、收藏目录 + 隐藏显示、零收藏空状态和过滤态禁用排序。

完成条件：目录收藏可被键盘和鼠标发现、触发与验证。

### 阶段四：全量回归与验收

1. 运行针对性测试：
   - `npm test -- tests/workspace/file-tree.test.ts`
   - `npm test -- tests/app/workspace-layout.test.tsx`
2. 运行完整测试与静态检查：`npm test`、`npm run lint`、`npm run build`（按 `package.json` 实际脚本确认）。
3. 手动验证本地服务：创建含 Markdown 文件的可见目录，收藏目录，切换收藏/隐藏/搜索；在应用外移动或删除该目录后刷新，确认失效收藏被清理。
4. 逐项勾选方案验收清单；任何失败先定位到相应阶段，不用 UI 例外掩盖底层状态错误。

## 交付物

- 收藏目录实现。
- 覆盖收藏投影、隐藏与搜索组合、Profile 隔离与刷新修剪的自动化测试。
- 更新后的方案/实施记录；如实施产生可复用架构决策，按 claw closeout 流程沉淀。

## 风险闸门

1. 阶段一纯函数测试未通过，不进入 App 或 UI 改动。
2. 阶段二未证明 Profile 保存与刷新修剪正确，不接入目录收藏 UI。
3. 阶段四任一隐藏、搜索、排序或 Profile 回归失败，不交付。
