# md-reader 收藏目录方案

## 方案概述

### 1. 总体目标和范围

本方案把既有“收藏文档”扩展为“收藏文件树节点”：用户可收藏 Markdown 文档或真实目录；开启“只看收藏”后，收藏文档直接显示，收藏目录连同其完整可见子树显示。该视图只是左侧树的投影，不创建磁盘目录、不改写 Markdown 正文，也不复制第二份文件树。

本轮范围包括目录收藏交互、收藏过滤语义、Profile 持久化、扫描后的陈旧路径清理，以及与隐藏、搜索、手动排序和已有文档路径变更链路的协作。收藏范围限定为当前 Markdown 文件树中可见的目录；空目录或仅含非 Markdown 文件的真实目录不进入现有树，因此不可收藏。

不包含跨项目收藏、批量管理、独立收藏面板或把收藏视图持久化为跨会话工作区模式。

### 2. 各阶段任务概要

1. **定义收藏节点与刷新边界**：把 `favoritePaths` 的正式语义扩展为“文件或目录路径”，建立扫描修剪规则；产出稳定的数据边界。
2. **升级收藏树投影**：替换当前仅匹配文件的 `filterFileTreeByFavorites()`，使收藏目录保留完整可见子树、普通收藏保留祖先上下文；产出纯函数和覆盖边界的单测。
3. **接入目录行交互**：将目录星标、右键动作和 App 回调接入既有文件树链路；产出与文档一致的可发现操作。
4. **恢复与回归验证**：在 Profile 水合、文件树刷新和路径变化后清理陈旧收藏；验证隐藏、搜索、排序、Profile 切换及空状态。

执行顺序为先数据和纯函数、再 UI、最后完整回归；这样视觉入口不会先于其规则真相落地。

### 3. 整体结构框架

```text
WorkspaceProfile.navigation.favoritePaths
        │  （文件与目录路径，按 Profile 持久化）
        ▼
App：水合 / 刷新修剪 / toggle / 保存
        │
原始有序树 → 隐藏可见树 → 收藏投影 → 搜索投影 → WorkspaceLayout
                                  │                    │
                                  └─ 收藏目录保留可见子树 ─┘
```

## 现状与问题

当前 `favoritePaths` 已保存在 `WorkspaceProfile.navigation`，`showFavoritesOnly` 是 `App` 的会话态。渲染顺序已经是“隐藏可见性派生 → 收藏过滤 → 搜索过滤”，这是本轮必须保留的职责边界。

但 `filterFileTreeByFavorites()` 仅在文件节点的路径精确命中时保留节点；目录不会被视为收藏对象。`WorkspaceLayout` 的星标和右键动作也只透传 `onToggleFavoriteDocument`。此外，`rewritePathCollections()` 与 `removePathCollections()` 只精确处理单一路径，无法覆盖目录的后代路径。

## 关键决策与规则

### 1. `favoritePaths` 保持字段名，升级为“收藏节点路径集合”

不新增第二份 `favoriteDirectoryPaths`。`favoritePaths` 可以保存当前树中任意文件或目录路径，仍归属于 `WorkspaceProfile.navigation`。

理由：文档与目录的收藏行为、持久化范围和开关完全相同；拆成两个字段会迫使每次过滤、迁移和清理合并两套真相。

约束：集合去重、规范化为相对路径；空目录不会出现在 Markdown 扫描构成的树中，因此其陈旧收藏会在下一次刷新时清理。

### 2. 收藏目录的匹配语义是“自身命中或存在被收藏祖先”

`filterFileTreeByFavorites(nodes, favoritePaths)` 需以可见树为输入，对每个节点判断：

- 当前路径精确收藏：文件保留；目录保留其当前可见的完整子树；
- 当前路径没有收藏但任一祖先目录已收藏：节点保留；
- 否则递归保留含有收藏后代的目录，作为必要上下文；
- 不满足以上条件的分支裁剪。

这样嵌套收藏不会生成重复节点：树只遍历一次，祖先目录收藏优先保留现有的单一子树投影。

### 3. 隐藏优先、收藏居中、搜索最后

固定链路继续为：

1. 有序原始树；
2. `createVisibleFileTree()` 处理隐藏；
3. `filterFileTreeByFavorites()` 处理收藏；
4. `WorkspaceLayout` 的 `filterFileTree()` 处理搜索。

因此，默认收藏目录不会显示隐藏后代；仅 `showHiddenItems = true` 时，它们才随已收藏目录进入候选树，并保留已有 `meta` 弱化语义。收藏与搜索、手动排序均不改变其上游真相。

### 4. 生命周期以刷新修剪为本轮边界

本轮不新增目录改名、移动或删除能力，也不承诺应用外目录变更后的收藏自动跟随。文件树刷新/水合时，使用当前树的文件、目录路径集合修剪不再存在的收藏项，并只在内容发生变化时保存 Profile。

既有文档路径变更链路保持不动。未来若新增目录文件管理功能，必须另开方案，以带路径边界的前缀迁移规则同步处理收藏、隐藏和排序状态。

### 5. 目录交互与文档交互同构

目录行与文件行均显示同一套可访问的收藏按钮：收藏后常显，点击不触发展开或打开动作；右键菜单增加“收藏目录”或“取消收藏目录”。回调统一更名为 `onToggleFavoritePath(path)`，避免 API 名称把能力锁死为文档。

“只看收藏”按钮文案可升级为“只看收藏”，零收藏空状态改为“当前还没有收藏内容”，覆盖文档与目录。

## 实施设计

### 阶段一：收藏节点数据与生命周期

涉及：`src/workspace/profile-store.ts`、`src/App.tsx`，以及对应 workspace/App 测试。

1. 保留 `favoritePaths: string[]` 的存储结构，为其增加“可含目录”的注释与规范化 helper。
2. 在树水合和 `refreshProjectTree()` 后，根据有序原始树收集有效节点路径，修剪陈旧收藏；仅变更时调用 `saveActiveProfileNavigation`。
3. 不改变 `showFavoritesOnly`：它继续是切 Profile、无项目或刷新后复位的会话态。

### 阶段二：收藏树投影

涉及：`src/workspace/file-tree.ts`、`tests/workspace/file-tree.test.ts`。

将现有过滤函数改为单次 DFS，参数为 `VisibleFileTreeNode[]` 和收藏路径集合。实现必须返回原节点或最小必要的目录克隆，不能修改输入树，也不能丢失 `meta`。

必须覆盖：收藏文件、收藏目录、收藏目录内未收藏文档、嵌套收藏、收藏祖先与子项、不可见隐藏项、显示隐藏项、无效收藏路径和空结果。

### 阶段三：文件树 UI 与回调命名

涉及：`src/App.tsx`、`src/app/AppShell.tsx`、`src/app/WorkspaceLayout.tsx`、`src/index.css`、相关组件测试。

1. 将 `onToggleFavoriteDocument` 全链路替换为 `onToggleFavoritePath`。
2. 在目录行渲染与文件相同的星标动作，补充明确 `aria-label`，并阻止事件冒泡，避免触发目录展开。
3. 在目录右键菜单加入收藏/取消收藏项；文档菜单继续保留对应动作。
4. `hasFavorites`、专用空状态和收藏筛选开关统一使用“收藏内容”语义。

### 阶段四：回归与恢复验证

涉及：`tests/app/workspace-layout.test.tsx`、`tests/app/app-session-restore.test.tsx`、`tests/app/app-profiles.test.tsx`（按实际测试分层调整）。

验证 Profile 隔离、切换后的过滤态复位、刷新修剪、搜索叠加、手动排序在过滤态只读，以及目录收藏的隐藏组合。现有文档收藏测试应完整保留，证明扩展没有回退既有行为。

## 验收清单

- [ ] 目录行可通过星标与右键收藏/取消收藏，且点击星标不触发展开。
- [ ] 收藏目录在“只看收藏”中显示自身及完整可见子树。
- [ ] 嵌套或重叠收藏不会重复渲染节点。
- [ ] 默认隐藏内容不因目录收藏出现；开启显示隐藏项后可出现且保持弱化。
- [ ] 收藏、搜索和排序投影顺序保持既有约束。
- [ ] 文档与目录收藏均按 Profile 保存；切换 Profile 后只看当前 Profile 数据。
- [ ] 刷新能清除外部文件变动留下的陈旧收藏项。
- [ ] 既有文档收藏、空状态、当前文档与标签页行为不回退。

## 风险与控制

1. **把目录收藏误实现为平铺集合**：必须通过树投影而非收集文件列表实现，保留原目录层级和排序。
2. **过滤污染展开与排序状态**：只投影渲染树，不改 `expandedFileNodes` 与 `manualNodeOrderByParent`。
3. **外部文件变化导致陈旧数据**：刷新时基于当前树统一修剪，避免仅依赖 UI 操作。
4. **未来目录操作扩范围**：目录改名、移动、删除不属于本轮；若后续新增，需另开方案定义完整路径迁移与草稿保护合同。
