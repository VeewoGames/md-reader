# md-reader 文档内链接与深链实施计划

> 状态：待评审。实施本计划需要用户另行明确授权；本文件不授权修改运行时代码。

## 方案概述

### 1. 总体目标和范围

本计划落实已确认的文档内链接与浏览器深链方案：所有 `ReadonlyMarkdownRenderer` 预览入口可在应用内打开当前项目文件树中的 `.md`、`.mdx` 文档；规范分享 URL 可复制、在新标签和刷新后恢复；文档锚点可在渲染完成后定位。

范围包含：安全路径解析、只读链接组件、正文链接专用保存导航门、锚点定位协议、URL 启动恢复与同步、受控失败反馈，以及纯函数、组件、App 和真实浏览器验证。

不包含：文件树点击语义变更、编辑器链接交互、自动改写改名/移动后的引用、旧 `/<文件>.md` 地址兼容、服务端 `.md` 路由回退。

### 2. 各阶段任务概要

1. **链接合同与纯函数**：实现并测试链接分类、路径规范化、文件树精确匹配、内容根校验与 heading fragment 规则。
2. **正文内部导航**：将只读 Markdown 链接接入专用异步导航入口；正文普通点击先保存当前草稿，文件树保持原行为。
3. **锚点与深链恢复**：建立渲染完成后的标题定位、规范 URL 生成、复制与启动恢复，并以导航请求标识避免异步乱序。
4. **验收与收尾**：补齐定向测试、构建和真实浏览器验证，记录边界与结果。

执行顺序严格为“合同 → 导航 → 深链/锚点 → 验收”。先锁定内容链接的规则，避免 UI 与 URL 各自形成不一致的路径解释。

### 3. 整体结构框架

```text
Markdown <a href>
  │
  ├─ 外部/非文档 ──────────────► 保留浏览器默认行为
  │
  └─ 项目内 Markdown
       │
       ▼
链接解析器（当前文档 + 文件树 + contentRoots）
       │
       ├─ 无修饰左键 ──────────► 保存当前草稿 → 加载目标 → 锚点 → 同步 URL
       └─ 修饰点击 ────────────► 浏览器新标签打开规范分享 URL

规范分享 URL → 启动恢复协调 → Profile/项目/文件树校验 → 同一导航加载链
```

## 已确认实施约束

- 内部目标必须精确命中文件树，且位于 `contentRoots`；客户端先消除 `../`，不向服务端传绝对路径或原始 `..`。
- `/docs/guide.md` 是带内容根前缀的项目精确路径；禁止同名文件猜测。
- 无修饰正文内部链接跳转前只保存当前活动文档；保存失败、冲突或读取失败时不切换目标、不改 URL。
- 正文无效内部候选（坏编码、越界、目标缺失或不在文件树）在所有点击手势下留在当前应用页面显示分类提示；修饰点击同样阻止默认新标签行为，不使用原始 `.md` 裸路径或安全替代 URL。
- 当前文档锚点 `#标题` 直接定位当前已渲染标题，不保存草稿、不重载文档；标题不存在时显示提示。
- 文件树继续调用既有 `handleDocumentSelect()`，不进入新增保存门，草稿保留在原标签。
- 正文链接打开目标后保持当前阅读视图：分栏预览继续分栏，普通锁定预览保持普通阅读。
- 修饰点击不被拦截，但内部链接渲染出的 `href` 必须是规范分享 URL。
- 分享 URL 使用 `project`、`profile`、`path` 和实际 heading ID；普通切换使用 `replaceState`，首版不支持 `popstate` 文档历史。
- URL 指向未知/非法目标时留在首页提示，并阻止本地会话恢复链打开旧活动文档。
- 首版不改写 Markdown 正文、不改编辑器交互、不兼容旧 `/<文件>.md` 地址。

## 阶段一：建立链接解析与标题规则

涉及：新增 `src/markdown/document-link.ts`（按实际命名调整）、`src/markdown/heading-outline.ts`、对应 `tests/markdown/`。

1. 从 `heading-outline.ts` 抽取公共 heading ID/slug 工具，使渲染、目录与链接片段共用同一规则。
2. 定义纯结果类型：外部链接、当前文档锚点、内部文档目标、无效链接；无效结果携带可显示的失败分类，不保留可导致裸路径导航的目标。
3. 解析 `href` 的片段、百分号编码、同目录、`./`、`../`、项目根路径与 `.md`/`.mdx`；规范化为 POSIX 项目相对路径。
4. 校验目标是否精确存在于文件树文档集合且位于 `contentRoots`；明确失败原因。

完成条件：纯函数覆盖中文、空格、`%23`、重复标题、无效编码、越界、多个内容根和同名文件；不复制标题 slug 规则。

## 阶段二：接入只读预览与正文导航门

涉及：`src/document-renderer/readonly-markdown-renderer.tsx`、`src/document-renderer/readonly-markdown-renderer-impl.tsx`、`src/app/WorkspaceLayout.tsx`、`src/app/AppShell.tsx`、`src/App.tsx`，以及 renderer/App 定向测试。

1. 为 `ReadonlyMarkdownRenderer` 逐层传入当前文档路径、文件树文档集合、`contentRoots` 与专用异步内部导航回调；覆盖普通锁定预览与分栏预览。
2. 定制 ReactMarkdown 链接组件：外链和非文档资源保留原属性；内部文档链接始终渲染规范分享 URL。
3. 无修饰主键点击合法跨文档链接时阻止默认行为，调用新增正文导航门；当前文档锚点直接交给锚点定位回调，不进入保存/加载门。无效内部候选在所有点击手势下阻止默认行为并显示分类提示。Ctrl/Cmd/Shift、中键与 `target="_blank"` 的合法跨文档链接不拦截；无效候选不打开新标签。
4. 在 App 抽取“保存当前活动草稿 → 加载目标文档 → 提交 React session 与 local-state”的专用异步入口；成功提交必须同步 `openDocumentPaths`、`activeDocumentPath`、阅读进度和当前视图模式。不要修改文件树 `handleDocumentSelect()` 的语义。

完成条件：正文普通点击安全跳转或受控失败；保存失败不跳转；新标签 `href` 不再是 `.md` 路径；文件树回归行为不变；分栏与普通阅读模式不被链接打断。

## 阶段三：锚点、URL 与启动恢复

涉及：`src/App.tsx`、`src/app/WorkspaceLayout.tsx`、可能新增 URL/导航辅助模块及对应测试。

1. 为 `WorkspaceLayout` 增加受控的待定位 heading ID：当前文档锚点直接定位；跨文档锚点在目标文档与标题 DOM 就绪后定位。两种情况均复用既有滚动规则，标题缺失时保留当前文档并提示。
2. 实现规范 URL 的生成、解析、复制与 `replaceState` 同步。
3. 调整启动协调：优先解析 URL 的 Profile/项目/路径，再加载该 Profile 的项目与文件树；无效 URL 走空会话启动路径，阻止旧 local-state 的活动文档恢复并显示提示。
4. 为正文/深链协调器的异步导航使用递增请求标识，仅允许最新请求提交 React session、local-state、锚点和 URL；不把该标识下沉为通用 `loadDocumentContent()` 的全局门。

完成条件：复制链接、新标签、刷新均能恢复目标；旧异步请求不能覆盖新目标；无效 URL 不会显示旧会话文档。

## 阶段四：验证与交付

1. 运行链接解析、渲染器、App 状态与服务端边界的定向测试，并执行构建；明确断言 `shouldServeSpaDocument('/x.md') === false`，必要时验证实际 HTTP 404。
2. 真实浏览器验证 Nocturnel 内已有文档链接：普通点击、修饰点击新标签、跨文档锚点、复制后刷新、无效 URL、正文无效链接和保存失败路径。
3. 运行 `git diff --check`，记录测试结果与已知仓库失败；确认没有改动编辑器、旧路径路由或 Markdown 正文。

## 验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 正文普通点击 `../目标.md` | 保存当前草稿后在应用内打开目标；不会请求 `.md` 路径 |
| 当前草稿保存失败 | 停留原文档，URL 不变，显示失败提示 |
| 正文无效/越界/不存在链接 | 所有点击手势均不请求 `.md` 裸路径或打开新标签；留在应用内显示分类提示 |
| 当前文档 `#标题` | 不保存、不重载；直接定位当前已渲染标题，缺失时提示 |
| Ctrl/Cmd/中键内部链接 | 不被拦截；新标签打开规范分享 URL 并恢复目标 |
| `目标.md#标题` | 打开目标并在渲染后定位实际 heading ID |
| 非法/缺失深链 | 停在首页提示，不恢复旧会话文档 |
| 文件树点击 | 保持既有切换语义和原标签草稿 |
| 分栏预览内部链接 | 目标文档保持分栏预览；普通锁定预览保持普通阅读 |
| 文档改名/移动 | 不改写其他 Markdown；失效引用在应用内提示 |
| 编辑模式与旧裸路径 | 不改变编辑交互；`/<文件>.md` 继续 404 |

## 风险与回退

- 链接解析不通过文件树与内容根校验时立即拒绝，保持服务端文件边界不变。
- 所有 URL 与会话写入由导航请求标识控制，避免异步回写污染当前阅读状态。
- 无效内部链接与无效深链均由受控失败路径处理，不把原始 `.md` 路径交还给浏览器。
- 本轮未修改 Markdown 正文、服务器路由或编辑器；若验证失败，可回退新增导航/URL 层，而不涉及内容数据迁移。
