# md-reader 文档内链接与深链方案（范围已确认）

> 状态：方案范围已确认，尚未获得运行时代码实施授权。本文可作为后续实施计划的依据。

## 方案概述

### 1. 总体目标和范围

目标是让用户在 MD Reader 的所有只读 Markdown 预览入口中点击同项目文档链接时，留在应用内打开正确文档，不再将 `/<文件名>.md` 交给浏览器而得到 404；同时提供可复制、可刷新恢复的浏览器深链。

本轮拟覆盖：内部 Markdown 文档链接解析、同文档与跨文档标题锚点、应用内标签页加载、地址栏同步、复制分享链接、失效链接反馈，以及与现有 `contentRoots`、文件树和自动保存链路的协作。

不包含：改写既有 Markdown 正文、自动修复重命名/移动后的所有引用、将任意磁盘路径暴露为 Web 路由、重构服务端文件访问安全边界，或在编辑模式中改变普通文本编辑手势。

### 2. 各阶段任务概要

1. **固化链接合同**：确认内部/外部链接分类、相对路径和多内容根规则；产出可独立测试的解析结果模型。
2. **接入所有只读预览入口**：在 `ReadonlyMarkdownRenderer` 中接入受控链接组件，新增“导航前保存门 + 打开目标”共享入口；产出应用内文档跳转。
3. **补齐锚点与失败反馈**：支持 `#标题`、`目标.md#标题`，并为解析失败、越界、目标缺失和标题缺失提供应用内反馈；产出可理解的阅读闭环。
4. **实现浏览器深链**：定义规范 URL，启动恢复、地址栏同步与复制链接；产出可分享、可刷新验证的访问入口。
5. **端到端验收**：覆盖纯函数、组件、App 集成和真实浏览器；产出不回归的链接导航体验。

执行顺序必须先确定链接合同，再接入 UI，最后处理深链与真实浏览器验证。这样不会把浏览器 URL 或 Markdown 原文的偶然写法变成运行时真相。

### 3. 整体结构框架

```text
Markdown href
    │
    ▼
链接分类与规范化（纯函数）
    ├─ 外部 / 非文档资源 ─────────► 浏览器默认行为
    └─ 同项目 Markdown 文档
          │  文件树精确命中 + contentRoots 校验
          ▼
  App 文档打开链（标签页 / 加载 / 自动保存门）
          │
          ├─ 文档已渲染 ──────────► 标题锚点定位
          └─ 成功打开 ────────────► 规范深链 URL / 复制分享链接
```

## 已验证现状与根因

1. `ReadonlyMarkdownRendererImpl` 使用 `ReactMarkdown`，只定制了代码块渲染，未接管 `<a>`；因此 Markdown 链接会由浏览器原生导航。
2. App 已具备按项目、Profile 与文档路径加载内容并管理标签页的链路，可作为内部导航的唯一打开入口；当前“拷贝链接”仅复制文档路径。
3. `server/web-ui.mjs` 只为无扩展名请求提供 SPA 回退；带 `.md` 的根路径不会命中 UI，实际返回 `Unknown route` 404。
4. 服务端拒绝绝对路径和原始 `..` 路径；客户端若支持 `../`，必须先转为不含 `..` 的项目相对路径。
5. 文件树扫描已将 `.md` 和 `.mdx` 识别为可打开文档；这是内部链接目标集合的现有真相。

## 推荐目标设计

### 1. 内部链接分类

只读预览中的链接按以下规则处理：

- **同项目 Markdown 文档**：候选目标为文件树中已发现的 `.md`、`.mdx` 文档，进入应用内导航。
- **当前文档锚点**：`#标题` 不重新加载文档，只在当前已渲染内容中定位标题。
- **跨文档锚点**：`目标.md#标题` 先打开目标文档，待渲染完成后定位标题。
- **外部和非文档链接**：`http:`、`https:`、`mailto:`、`tel:`、协议相对 URL 及非 Markdown 资源保持浏览器默认行为。
- **修饰点击**：Ctrl/Cmd/Shift、中键或明确 `target="_blank"` 不应被普通应用内导航吞掉；内部文档链接以规范分享 URL 作为 `href`，使新标签可恢复正确目标。

### 2. 路径解析与安全门

解析器输入应为“当前文档项目相对路径、原始 `href`、当前文件树文档集合与内容根信息”，输出为分类后的安全导航意图，而非直接输出浏览器 URL。

- `同目录文件.md`、`./文件.md`、`../目录/文件.md` 相对当前文档目录解析，并在客户端规范化为 POSIX 项目相对路径。
- `/路径/文件.md` 不再作为浏览器站点根路径使用，而按下文确认后的“项目逻辑根”规则解析。
- 规范化结果必须同时满足：不含绝对路径、不含未消除的 `..`、位于允许 `contentRoots` 内、且精确出现在当前文件树文档集合中。
- 不做文件名模糊搜索；同名文档必须由链接作者写出足以唯一定位的路径。
- 无效百分号编码、反斜杠、越界、非 Markdown 目标与不存在目标均返回受控失败，不回退到浏览器的本地服务根路径。

### 3. 浏览器深链协议

推荐正式 URL 为查询参数，而不是直接使用 `.md` 路径：

```text
http://127.0.0.1:8797/?project=<projectId>&profile=<profileId>&path=<encodedDocumentPath>#<encodedHeadingId>
```

原因：该结构能明确项目、Profile、文档与锚点，避免与静态资源、服务端 API 和 `.md` 文件路径路由冲突。

启动恢复必须按以下顺序进行：解析并校验 URL → 选择 URL 指定的 Profile → 加载该 Profile 的项目注册与文件树 → 定位项目和文档 → 通过导航入口加载内容与锚点。URL 指定的 Profile/项目/路径不存在或非法时，留在应用首页并给出提示；不得降级猜测默认项目。

成功打开文档时用 `history.replaceState` 同步 URL；“拷贝链接”复制完整规范 URL。首版不将文档切换写入浏览器历史，也不处理 `popstate` 文档恢复。异步导航必须携带递增请求标识，只有最新请求可提交文档、锚点与 URL，避免较早请求晚到后覆盖新目标。首版不兼容旧 `/文件.md` 地址，旧地址保持 404；只保证新生成的规范分享 URL 可打开。

### 4. 锚点协议

规范分享 URL 的片段必须使用实际渲染的 heading ID。Markdown 中的原始 `#标题` 片段按现有 `createHeadingSlug()` 规则转换；重复标题必须以实际 ID（例如 `#设计目标-2`）消歧。`文档.md#标题` 先打开目标文档，待 `WorkspaceLayout` 确认标题 DOM 已渲染后再滚动；不能在 `loadDocumentContent()` 返回后直接查询 DOM。

### 5. 失败反馈

链接失败必须留在应用内，至少区分：

- 链接格式无法解析；
- 规范化后越出允许内容根；
- 目标不在当前文件树；
- 读取时目标已被外部删除；
- 文档已打开但目标标题不存在。

每种情况显示包含原始链接或目标路径的简短提示。标题不存在时保留已打开的目标文档，不能回退到浏览器错误页。

## 已确认决策

### 1. 内部文档链接覆盖范围

**已确认**：所有使用 `ReadonlyMarkdownRenderer` 的只读预览入口均支持文件树中 `.md` 与 `.mdx` 的内部跳转；外部和非 Markdown 资源保持浏览器行为。

影响：普通锁定预览与分栏预览遵守同一规则，避免用户因视图不同再次遇到 404。

### 2. 内部链接的标签页与未保存内容行为

**已确认**：无修饰左键跳转前只保存当前活动文档；保存或冲突处理失败则取消跳转，保留当前文档与 URL。该门是本轮新增的共享导航能力，不能误称为复用 `handleDocumentSelect()` 的既有行为。Ctrl/Cmd/中键等新标签手势保留浏览器预期，是否支持应用内新标签需单独定义。

影响：避免点击链接丢失未保存编辑，也避免在本轮隐式扩展标签行为。

### 3. 浏览器历史与旧地址兼容

**已确认**：首版支持规范查询参数 URL 的刷新恢复与复制；文档切换用 `replaceState`，不为普通阅读建立浏览器前进/后退文档历史，也不实现 `popstate` 恢复。旧 `/文件.md` 地址不兼容，保持 404。

影响：实现更稳、更少路由冲突；历史地址继续保持 404，不建立受控重定向。

### 4. 标题锚点

**已确认**：规范 URL 使用实际 heading ID；Markdown 原始标题片段按现有 slug 规则转换，重复标题必须使用带序号的实际 ID。找不到标题时保留已打开文档并显示提示。

### 5. 无效深链

**已确认**：未知或缺失 `project`、`profile`、`path`，重复参数，解码后非法或越界的路径，以及恢复失败的文档，均留在应用首页并显示明确提示；不降级到默认项目、不猜测目标，也不跳到浏览器 404 页。

### 6. 多内容根下 `/路径.md` 的语义

**已确认**：`/` 表示项目物理根的精确相对路径，且路径必须明确携带内容根前缀，例如 `/docs/guide.md`；多内容根下禁止按文件名搜索或自动猜测。

影响：路径可预测，且不会因未来增加内容根而打开错误的同名文档。

### 7. 内部链接的新标签语义

**已确认**：Ctrl/Cmd/Shift、中键或明确 `target="_blank"` 的内部文档链接不被应用内导航拦截，但其 `href` 必须是完整规范分享 URL，因此新标签同样可恢复正确的项目、Profile、文档与锚点，不能继续使用原始 `.md` 路径。

影响：保留浏览器新标签习惯，同时消除新标签打开 `.md` 404 的问题。

### 8. 文件树点击的保存边界

**已确认**：新增保存门仅用于文档正文中的无修饰内部链接；文件树继续使用既有 `handleDocumentSelect()` 切换语义，不强制保存当前草稿，草稿保留在原标签页。

影响：链接跳转不会丢当前草稿，也不会因本功能改变既有文件树切换体验。

## 已确认首版非目标

### 1. 文档改名或移动后的引用

首版不批量改写 Markdown 正文，也不维护永久别名；移动后失效链接按“目标不存在”反馈。若未来需要自动更新引用，必须另立数据治理方案。

影响：控制本轮范围，避免一次文件操作引发跨文档隐式内容修改。

### 2. 编辑模式边界

首版只改变只读预览中的链接点击；编辑器不拦截普通输入、光标操作或链接点击。若编辑器已有独立“打开链接”动作，后续再接入同一解析器。

影响：避免破坏写作交互，同时确保后续不会出现两套路径规则。

### 3. 历史 `/文件.md` 地址兼容

首版不为 `/<文件>.md` 建立别名、重定向或 SPA 回退；旧地址保持 404。只有新复制或新渲染出的规范分享 URL 承诺可恢复目标文档。

影响：不改变服务端静态资源与路径安全边界，避免把历史裸路径解析扩展为路由兼容工程。

## 实施设计

### 阶段一：链接意图解析器

涉及：新增 `src/markdown/` 下的纯函数模块与定向测试。

1. 定义 `InternalDocumentLink`、`ExternalLink`、`AnchorLink`、`InvalidLink` 等显式结果类型；解析器显式输入当前文档路径、文件树文档集合和 `contentRoots`。
2. 分离片段、完成 URL 解码、路径规范化、文件树精确匹配与允许内容根校验。
3. 将标题锚点作为导航意图的一部分，复用现有标题 ID 生成规则，而非再生成一套 slug。

### 阶段二：只读预览导航接线

涉及：`src/document-renderer/readonly-markdown-renderer*.tsx`、`src/app/WorkspaceLayout.tsx`、`src/app/AppShell.tsx`、`src/App.tsx`。

1. 为 `ReadonlyMarkdownRenderer` 增加当前文档路径、可打开文档集合、`contentRoots` 与专用异步内部导航回调；列出普通锁定预览与分栏预览的接入矩阵。
2. 使用 ReactMarkdown 的链接组件处理无修饰点击；外部链接保持原有行为，内部链接的修饰点击保留浏览器默认打开方式但渲染为规范分享 URL。
3. App 侧新增“保存当前活动草稿 → 打开目标 → 提交 URL”的导航门，仅供文档正文中的无修饰内部链接使用；文件树继续调用既有 `handleDocumentSelect()`，禁止在渲染器中直接访问本地服务 URL。

### 阶段三：锚点、失败提示与深链

涉及：App 状态、标题大纲/渲染辅助、`history` 封装、顶部或右键的复制链接动作。

1. 目标文档加载并由 `WorkspaceLayout` 确认渲染后再执行标题定位；找不到标题时保留目标文档并显示提示。
2. 解析并生成规范查询参数 URL；应用启动以 URL 的 Profile/项目为优先入口恢复文档和锚点；使用导航请求标识避免异步乱序覆盖。
3. 将“拷贝链接”文案和内容改为完整分享 URL。

### 阶段四：验证

1. 纯函数：同目录、`./`、`../`、根路径、多内容根、中文、空格、锚点、`.mdx`、越界和无效编码。
2. 组件：无修饰内部链接调用异步导航回调；外链不被拦截；内部链接的 Ctrl/Cmd/Shift/中键及 `target="_blank"` 不被拦截，且其 `href` 为包含 `project`、`profile`、`path` 与锚点的规范分享 URL。
3. App 集成：保存门、标签加载、标题定位失败、缺失文档提示与 URL 同步。
4. 真实浏览器：从 Nocturnel 文档点击现有链接；修饰点击内部链接的新标签可恢复目标；复制链接后新标签和刷新恢复；确认地址栏不再出现 `.md` 404。

## 风险与控制

1. **路径解析绕开服务端边界**：解析器只生成项目相对路径，并以文件树精确命中与 `contentRoots` 双重校验；服务端拒绝规则不放宽。
2. **多个内容根导致误跳转**：禁止按文件名猜测；根路径要求明确、唯一的项目相对位置。
3. **阅读器与编辑器规则分叉**：首版仅接入只读预览，但解析器独立于 UI，为后续编辑器动作复用准备单一规则源。
4. **深链反复写入浏览器历史或异步覆盖**：普通文档切换使用已确认的 `replaceState` 合同；以导航请求标识阻止旧请求覆写较新的文档与 URL。
5. **移动或改名引发全库内容修改**：本轮不改写引用；需自动更新时另行评估引用扫描、冲突与回退。
