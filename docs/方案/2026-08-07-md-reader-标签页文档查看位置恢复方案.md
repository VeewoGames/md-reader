# md-reader 标签页文档查看位置恢复方案（范围已确认）

> 状态：方案范围已确认，尚未获得运行时代码实施授权。本方案覆盖同次标签切换及刷新/重启后的查看位置恢复。

## 方案概述

### 1. 总体目标和范围

目标是让用户在长 Markdown 文档阅读过程中切换到其他标签页后，返回原标签时继续停留在此前的查看位置；刷新或重启应用后，已恢复的标签页也应回到各自上次保存的位置。

本轮复用已存在的 `WorkspaceTab.lastKnownScrollTop` 和 `WorkspaceLocalState.tabStateByDocument`，将其从“已定义但未接线”的状态字段接入阅读画布的采集、恢复与持久化链路。位置以项目内文档路径为键、以像素 `scrollTop` 为值；同一文档在不同标签中不会重复打开，因此不需要引入独立的标签实例身份或第二套存储。

本轮包含：常规/分栏视图共用阅读画布的位置采集、标签切换恢复、应用启动会话恢复、移动与删除路径的既有迁移链保持有效、异步加载竞态防护，以及深链标题定位的优先级保护。

本轮不包含：按 Profile 隔离位置、按阅读/编辑模式分别保存位置、以标题语义代替像素位置、跨设备同步、阅读进度 UI、文档内容变更后的智能语义锚定，或修改编辑器内部光标/滚动行为。

### 2. 各阶段任务概要

1. **固化位置恢复合同**：明确单一状态真值、位置键、默认值、优先级与失效值处理；预期成果是可由实现和测试共同遵守的恢复顺序。
2. **接通画布与会话状态**：让 `WorkspaceLayout` 采集阅读画布位置并在文档稳定渲染后恢复；预期成果是同次标签切换可回到原位置。
3. **接通本地持久化与生命周期收口**：将节流后的最新位置合入既有 `tabStateByDocument`，并在切换、关闭和项目切换前刷新；预期成果是刷新/重启、改名和删除场景不丢失或残留位置。
4. **验证竞态、导航和真实阅读体验**：补齐组件、App 集成与浏览器长文档测试；预期成果是位置恢复不会覆盖最新标签，也不会破坏深链标题跳转。

执行顺序必须先冻结恢复合同，再接通 UI 和状态，随后才写持久化与验收。这样不会把某一次 DOM 渲染时序或 IndexedDB 写入时机误设为状态真相。

### 3. 整体结构框架

```text
阅读画布 .panel__content--canvas
    │ scroll（passive + rAF 采样）
    ▼
WorkspaceLayout.onDocumentScrollTopChange(scrollTop)
    │
    ▼
App：当前 activeTab 的 lastKnownScrollTop（内存真值）
    │ 节流 / 切换前 flush
    ├─► WorkspaceSession.tabs[tabId]
    └─► WorkspaceLocalState.tabStateByDocument[documentPath]
                │
                ▼
       启动恢复 / 标签激活 / 内容渲染稳定
                │
                ▼
       WorkspaceLayout canvas.scrollTo({ top, behavior: 'auto' })

深链或跨文档标题定位 ──► 标题锚点定位优先，覆盖普通位置恢复
```

### 4. 复核后强制约束

为防止滚动时序在真实阅读中产生回跳或丢失，本方案的实现必须额外遵守以下约束：

1. `navigationEpoch` 是本功能唯一的导航令牌；每个 epoch 内的普通恢复只拥有一个一次性的 `restoreRequestId`。标题导航创建后必须取消同文档、同 epoch 的普通恢复意图，而不是仅凭 props 变化执行或抑制 effect。
2. local state 的 read-modify-write 必须经过 `App` 内项目级唯一 `mutateLocalState` 串行入口。位置、标签、模式、导航、关闭和路径生命周期等本轮会并发修改 local state 的写入点都在任务执行时重读最新 normalized state，再 patch 自己的字段；不能让任何一条路径用陈旧快照整对象覆盖其他更新。
3. 所有改变活动文档的入口在异步加载前都要递增并捕获 `navigationEpoch`，连同旧画布的 `{ projectId, tabId, documentPath, scrollTop }` 先 flush；加载结果只能在 epoch 仍为当前时调用 `applyLoadedDocument()`、改变 active tab 或创建恢复意图，不能等 `await` 后再按“当前活动标签”归属。
4. `canvas` 原生 scroll 监听的添加和移除必须使用同一个被捕获的 DOM 节点与 handler identity；恢复和采样可共享同一个 rAF，不能在 render 阶段叠加 inline `onScroll`。

## 已验证现状与根因

1. `WorkspaceTab` 已拥有 `lastKnownScrollTop`，`WorkspaceLocalState` 已拥有按文档路径保存的 `tabStateByDocument`；旧单文档位置也已被兼容迁移。
2. 工作区启动恢复会使用 `tabStateByDocument` 重建每个标签的 `lastKnownScrollTop`；文档移动与删除也会迁移或移除这些路径键。
3. 当前 `WorkspaceLayout` 的 canvas 滚动监听仅用于右侧目录的活动标题同步，未向 `App` 回传 `scrollTop`；`App` 也没有把 active tab 的位置下传给 Layout 恢复。因此字段不会随实际阅读更新，标签切回时自然只能停留在当前画布残留位置或顶部。
4. 跨文档深链已经使用异步导航请求编号并在渲染后处理 `pendingHeadingId`。普通位置恢复若没有同等的活动文档守卫，会在 A → B → A 快速切换时把迟到加载的旧位置应用到错误标签。

## 已确认设计

### 1. 状态归属与持久化边界

- **内存真值**：`WorkspaceSession` 中每个 `WorkspaceTab.lastKnownScrollTop`。
- **持久化投影**：当前项目的 `WorkspaceLocalState.tabStateByDocument[documentPath]`。
- **键**：规范项目相对路径；不得按标题、数组下标或 DOM 节点身份保存。
- **默认值**：没有记录、首次打开或无效数值时为 `0`。
- **范围**：位置属于项目，不属于 Profile；切换 Profile 不创建第二份同项目位置记录。

这使当前已有的路径迁移、删除清理和启动会话恢复继续适用，避免 `lastKnownScrollTop` 与另一份“阅读进度”互相覆盖。

### 2. 恢复时机与优先级

每次文档导航产生递增的 `navigationEpoch`；普通恢复意图必须包含目标 `projectId`、`tabId`、`documentPath`、`top`、所属 `navigationEpoch` 与该 epoch 内递增的 `restoreRequestId`。恢复仅在以下条件同时满足后执行：epoch 仍为当前、该意图仍是最新且未被取消、目标标签仍是当前活动标签、`currentDocumentPath` 仍等于目标文档路径、目标内容已完成当前轮渲染。至少延后到下一帧，确保画布 `scrollHeight` 已可读取。

优先级如下：

1. 有效的 `pendingHeadingId`（深链、正文跨文档标题跳转）先定位标题，并取消同一导航周期的普通位置恢复；
2. 否则恢复该文档的 `lastKnownScrollTop`；
3. 没有历史位置则从顶部开始。

恢复值必须限制到 `0..max(0, scrollHeight - clientHeight)`。普通恢复在一个导航周期内只允许消费一次，不得在标题列表、图片或 Mermaid 的后续异步变化时重新激活，否则会把用户手动滚动或已完成的标题定位拉回旧位置。

### 3. 采集、节流和 flush

- 画布原有的 passive `scroll` 监听可在同一帧采样中读取 `canvas.scrollTop`，并同时保留目录高亮逻辑。监听 effect 需先捕获 `const canvas = canvasRef.current`，安装和 cleanup 均使用该同一节点与 handler identity。
- 内存中的 active tab 可以按 rAF 更新，避免每个原生事件触发 React 状态更新。
- 本地存储写入必须 debounce；切换标签、关闭标签、开始切换项目/项目 Profile、开始异步文档加载前应先捕获并 flush 最后一次采样值。组件卸载仅作 best-effort，不能作为可靠持久化验收的唯一依据。
- `mutateLocalState` 是项目级唯一 read-modify-write 队列；位置 debounce、标签切换、模式变化、文档导航、关闭和路径迁移/删除等本轮会并发保存 local state 的入口均通过它。任务真正执行时重新读取最新 normalized state，再 patch 当前字段，不能用创建 timer 时的陈旧快照整对象覆盖其他标签较新的位置。
- 路径移动、删除、关闭和项目切换先 flush，再迁移/移除路径；延迟写入携带 `projectId + documentPath + generation` 守卫，生命周期操作完成后取消旧 generation，防止旧路径被 timer 重新写回。

### 4. 视图与导航边界

阅读画布是常规锁定视图和分栏预览的共同容器，首版按同一文档共享一个位置。编辑器自身不接收、也不写入此位置；从编辑态进入可阅读画布时，仍只恢复该文档的统一查看位置。

文件树打开、顶部标签切换、文档正文链接和启动恢复都应复用同一“活动文档变化后尝试恢复”的机制。正文深链已有的标题导航语义保持更高优先级，不能先恢复旧位置再跳标题而造成明显闪动。

## 实施设计

### 阶段一：定义位置恢复接口

涉及：`src/App.tsx`、`src/app/AppShell.tsx`、`src/app/WorkspaceLayout.tsx`、`src/workspace/workspace-session.ts`。

1. 为 `WorkspaceLayout` / `AppShell` 增加只表达画布位置的输入输出接口，例如带 `documentPath`、`tabId`、`navigationEpoch` 和 `restoreRequestId` 的恢复意图，以及带相同归属的 `onDocumentScrollTopChange`。
2. `App` 从 active tab 派生当前要恢复的位置；接收回调时以 project id、tab id 与 document path 共同确认归属，再更新对应 tab。
3. `navigationEpoch` 是唯一导航令牌；将恢复请求建模为“目标文档 + 位置 + epoch 内的 restoreRequestId”的一次性意图，而不是任意 props 变更都直接 `scrollTo`；标题导航创建时必须取消该普通意图。
4. 对无效、负数、NaN 和超范围位置建立统一归一化函数，供恢复与持久化复用。

完成条件：单一位置字段、回调方向和恢复守卫明确；不引入第二套 Store、Context 或路径映射。

### 阶段二：接入阅读画布采集与恢复

涉及：`src/app/WorkspaceLayout.tsx`。

1. 在现有 `canvasRef` 的 scroll 处理中按帧采集 `scrollTop`，调用上层回调；保持目录 active heading 的现有行为。安装/移除监听必须引用同一 captured canvas，cleanup 同时取消尚未执行的 rAF。
2. 在目标文档内容和当前渲染稳定后，以 `canvas.scrollTo({ top, behavior: 'auto' })` 消费一次恢复意图。
3. 恢复前校验 `navigationEpoch`、活动 tab 与文档路径；标题导航开始时取消普通意图，标题完成后也不得再执行该已取消意图。
4. 同一导航周期只能恢复一次；后续 headings、图片或 Mermaid 更新不得无条件二次覆盖用户行为。

完成条件：不刷新页面的 A → B → A 标签切换能可靠恢复 A 的位置；新文档仍从顶部开始。

### 阶段三：持久化和生命周期收口

涉及：`src/App.tsx`、`src/workspace/local-state.ts`、既有路径变更测试。

1. 提供 `App` 内项目级唯一 `mutateLocalState` 队列：每个任务执行时才读取最新 local state、对字段做最小 patch 再保存。位置 debounce 与本轮涉及的标签、模式、导航、关闭、路径迁移/删除等 local state 写入全部通过该入口，使用 debounce 降低 IndexedDB 写频率但不分裂 writer。
2. 在标签切换、关闭、项目/Profile 切换和文档异步加载**开始前**递增并捕获 `navigationEpoch`，同时捕获 `{ projectId, tabId, documentPath, scrollTop }` 并 flush；不得在异步完成后再以“当前 active tab”归属旧画布位置。
3. tab、文件树和正文链接的异步加载都携带 caller 的 `navigationEpoch`；只有该 epoch 仍为当前时才应用文档内容、更新 active tab、提交 local state 与创建恢复意图，迟到结果直接丢弃。现有正文链接导航的请求编号模式可作为复用起点，不另建 fetch 层。
4. 路径改名、移动、删除和关闭必须先 flush，再调用既有迁移/清除链；取消携带旧路径或旧 generation 的延迟任务，禁止完成后复活孤儿键。
5. 复用既有启动恢复逻辑将持久化位置重建回 tabs。`readingProgressByDocument` 保留为当前未消费但随路径迁移的本地字段，新增位置写入不得改动它。

完成条件：刷新/重启后的会话恢复可回到每个文档的独立位置，且路径生命周期不留下孤儿记录。

### 阶段四：验证

1. **组件测试**：模拟 canvas 的 `scrollTop` / `scrollTo`；验证初次打开为 0、A → B → A 恢复、超范围 clamp、listener 使用同一节点清理，以及标题定位完成后不再发生旧位置 `scrollTo`。
2. **App 集成测试**：验证采样值写入正确标签与 local state；首次异步加载、快速 A → B → A、刷新恢复、关闭标签和项目切换不发生旧位置串写；位置 debounce 与正文链接导航、模式变化、关闭的交错写会同时保留各自 patch；迟到 load 不会重选中旧 tab 或创建恢复意图；位置写入不修改 `readingProgressByDocument`。
3. **路径生命周期测试**：在已有 `document-path-mutation` 测试上补充移动后位置保留、删除后位置移除，以及取消的延迟写入不会复活旧路径。
4. **真实浏览器验证**：在长 Markdown 文档中滚到明确位置，切换至少两个标签再返回；刷新后复验；点击含 `#heading` 的跨文档链接，确认停在标题而非旧位置。
5. 执行定向测试、`npm run build` 与 `git diff --check`；全量仓库检查如有既有失败，单独记录而不混称为本功能失败。

完成条件：上述用例全部通过，并以浏览器实测证明真实滚动容器的行为与测试一致。

- [ ] A 文档滚到非零位置，切到 B 后再选 A，A 回到原位置。
- [ ] 多个已打开文档各自保存独立位置，不相互覆盖。
- [ ] 新打开、没有记录、无效值或内容变短的文档安全落在合法范围内。
- [ ] 刷新或重启后，恢复出的标签页分别回到各自保存的位置。
- [ ] 快速切换或异步加载乱序不会将旧文档位置套到当前文档。
- [ ] 迟到的标签或文件树加载不会重新激活旧文档、写回旧 local state 或创建恢复意图。
- [ ] 带标题片段的深链与正文跨文档标题跳转优先定位标题。
- [ ] 标题定位成功并清除 `pendingHeadingId` 后，不会再以旧 `lastKnownScrollTop` 发生第二次回跳。
- [ ] 文档移动/改名后位置随新路径保留；删除和关闭后的条目按现有会话清理规则移除。
- [ ] 改名、删除、项目切换后，已取消的 debounce 写入不会重新写入旧路径；位置写入不修改 `readingProgressByDocument`。
- [ ] 编辑器光标、输入和其内部滚动行为未改变。
- [ ] 定向自动化、构建、差异检查与真实浏览器长文档验证通过。

## 风险与控制

1. **DOM 尚未完成布局即恢复，导致位置不准**：以目标文档、加载完成和下一帧三道条件恢复；必要时只在本轮导航中重试一次。
2. **高频滚动导致存储写放大或陈旧覆盖**：内存按帧采样、持久化 debounce；唯一 `mutateLocalState` 队列在执行时重读状态，所有本轮 local-state writer 都通过它，生命周期边界先 flush 并取消失效 timer。
3. **异步导航乱序污染位置**：以唯一 `navigationEpoch` 守卫 tab、文件树和正文链接的加载结果；旧回调不得应用文档、改变 active tab、写入或恢复，活动文档变化前先捕获旧画布归属。
4. **标题导航与位置恢复冲突**：标题锚点创建时取消普通 `restoreRequestId`，标题完成后该普通意图仍保持失效，避免二次回跳。
5. **两套进度字段分叉**：`readingProgressByDocument` 不作为本功能的新写入目标；除非未来另立阅读进度 UI 需求，否则位置唯一权威是 `tabStateByDocument` 与 tab 字段。
