# md-reader 最近文档视图方案

## 方案概述

### 1. 总体目标和范围

本方案在左侧文件树搜索栏中、收藏按钮右侧增加「最近」按钮。用户开启后，以扁平列表查看当前项目中最近创建或修改的 Markdown 文档，不再受文件夹层级和手动树排序影响。

最近列表的排序依据为每个文档的 `recentAtMs = max(createdAtMs, modifiedAtMs)`，按降序排列。隐藏是不可绕过的可见性边界：显式隐藏的文档、显式隐藏文件夹，以及这些文件夹的所有后代，在最近视图中始终不可见；即使正常文件树当前处于 `showHiddenItems = true` 状态也不例外。

本轮包含跨平台文件时间元数据采集、本地服务缓存、最近视图投影、按钮交互、搜索叠加、空状态和测试。不包含 Git/编辑器级版本历史、最近视图持久化、时间范围筛选、分页、按文件夹聚合或跨项目汇总。

### 2. 各阶段任务概要

1. **建立跨平台文档时间合同**：服务端扫描 Markdown 文件时采集并缓存创建、修改与最近时间；前端接收结构化条目而非仅路径。成果是稳定的数据合同与缓存兼容处理。
2. **建立严格隐藏后的最近投影**：在完整文件树中先应用强制隐藏规则，再展平文档并按最近时间稳定排序。成果是不泄露隐藏内容的纯函数与测试。
3. **接入互斥浏览与文件树 UI**：新增「最近」按钮，使其与收藏互斥；最近视图复用文件选择与搜索，但禁用树语义下的拖拽操作。成果是可理解、可访问的浏览入口。
4. **完成刷新与回归验证**：覆盖保存、创建、外部刷新、profile 切换、隐藏、搜索和同名文件等路径。成果是经构建和定向测试验证的交付。

执行顺序必须是数据合同、投影规则、UI 接入、回归验证。UI 不能先于“时间与隐藏”两条真相落地，以免产生排序不更新或隐藏泄露。

### 3. 整体结构框架

```text
文件系统（跨平台 stat）
        │
        ▼
服务端扫描与树缓存
  { path, createdAtMs, modifiedAtMs, recentAtMs }
        │
        ▼
App：原始树 / Profile hiddenPaths / 会话浏览模式
        │
        ├─ 普通：原始树 → 当前隐藏可见性 → 搜索
        ├─ 收藏：原始树 → 当前隐藏可见性 → 收藏投影 → 搜索
        └─ 最近：原始树 → 强制隐藏 → 展平文档 → 最近排序 → 搜索
                                                            │
                                                            ▼
                                                   WorkspaceLayout
```

## 已确认的产品决策

### 1. 收藏与最近是互斥的会话浏览模式

`showFavoritesOnly` 与新增的 `showRecentOnly` 不同时为 `true`：

- 点击「最近」：开启最近并关闭收藏；
- 点击「收藏」：开启收藏并关闭最近；
- 再次点击当前已开启按钮：回到普通文件树；
- 切换项目、切换 Profile、无项目或重新初始化时：两个开关都回到关闭状态。

理由：收藏回答“我固定关注什么”，最近回答“刚刚变化了什么”。允许同时开启会变成“最近的收藏”，会使两个并列入口的含义不明确；若未来确有需求，应另设组合筛选而非隐式叠加。

这两个开关都是会话态，不写入 `WorkspaceProfile.navigation`，不污染用户长期的文件树偏好。

### 2. 最近视图只显示文档，不渲染目录

最近视图的输出是 `VisibleFileTreeFileNode[]` 的根级列表。每行主标题使用文件名，并在同一按钮内渲染 `aria-hidden` 的项目相对路径副标题；不设置 `title`，解决不同目录下同名文件不可区分的问题，同时保持既有文件按钮的可访问名称稳定。

目录不作为最近列表项目，也不按目录的时间影响子文档排序。文件的打开、收藏、隐藏、重命名、删除等已有路径操作仍以其原始相对路径为准。

### 3. 隐藏优先且在最近模式强制生效

普通和收藏视图维持既有规则：`showHiddenItems` 决定隐藏节点是否进入当前可见树。最近视图改用严格规则：无论 `showHiddenItems` 当前值为何，都以 `showHiddenItems: false` 派生可见树，再从中收集文档。

因此，隐藏不是“在最近里被排序得靠后”，而是根本不成为候选项。文件夹隐藏的后代也因 `isHiddenByAncestor` 被排除。

### 4. 最近时间是文件系统时间，不是版本历史

本地服务使用 Node.js `fs.stat` 的跨平台字段取得：

- `modifiedAtMs`：`mtimeMs`；
- `createdAtMs`：有效的 `birthtimeMs`；
- `recentAtMs`：两者的较大值。

若 `birthtimeMs` 不是有限数值或小于零，则以 `mtimeMs` 作为 `createdAtMs` 与 `recentAtMs` 的降级值。文件系统即使返回了数值，应用也不能自动判断它是否保留了原始创作日期；这属于平台或同步工具的语义限制，而不是可由产品代码猜测的条件。相同 `recentAtMs` 时按规范化相对路径升序排序，保证列表在刷新后不无故跳动。

不得引入 Windows 路径、PowerShell、注册表、NTFS 专属 API 或仅 Windows 可用的时间字段。该语义代表“当前文件系统可观察到的最新创建/修改时间”，不承诺恢复原始创作日期，也不替代 Git 修订时间。

### 5. 最近视图不提供树内拖拽排序或拖放移动

最近列表的顺序由时间决定，不能写回 `manualNodeOrderByParent`。在此模式下禁用节点拖拽重排与将文档拖入目录的操作，避免用户误以为移动了真实文件或可以手动改变最近顺序；其他明确的文件操作沿用既有菜单入口。

## 数据与职责边界

### 服务端：扫描结果和缓存是时间真相

现有 `scanMarkdownTree()` 与项目树缓存只保存 `string[]` 路径，无法为未打开的文档排序。本轮将其升级为结构化条目，例如：

```ts
interface ProjectTreeDocumentEntry {
  path: string
  createdAtMs: number
  modifiedAtMs: number
  recentAtMs: number
}

interface ProjectTreeSnapshot {
  entries: ProjectTreeDocumentEntry[]
}

type BridgeReadyTreePayload = {
  status: 'ready'
  snapshot: ProjectTreeSnapshot
  refreshId: string | null
}

type BridgeDocumentSavePayload = BridgeDocumentPayload & {
  treeEntry: ProjectTreeDocumentEntry
  treeStatus: 'dirty'
}
```

`ProjectTreeSnapshot.entries` 是项目树扫描的唯一真相；现有调用所需的 `paths` 只能由 `entries.map((entry) => entry.path)` 在同一边界派生，不能另保留第二套路径扫描或仅时间请求。扫描器在枚举到 Markdown 文件后读取一次元数据；缓存快照存储条目数组，并提升快照版本，以避免旧的仅路径缓存被当成完整数据。bridge 的 ready 与 wait 完成响应均返回 `BridgeReadyTreePayload`；indexing/refreshing 响应只返回状态和 `refreshId`。`WorkspaceProvider` 替换 paths-only 公共方法为 `getProjectTreeSnapshot()` 与 `refreshProjectTreeSnapshot()`，App 的加载、刷新及每个节点变更调用点都只消费该快照并在同一状态提交中更新 `fileTree` 与时间索引。

服务端缓存的有效性仍由现有刷新流程负责：显式刷新必须重扫时间；创建、重命名、移动、删除保持既有的 `markMutation()` 失效路径。文档保存成功后也必须调用 `markMutation()`，不能继续让旧快照在 freshness 窗口内作为最近排序依据；写入响应固定为 `BridgeDocumentSavePayload`，App 立即使用 `treeEntry` 更新该路径的时间索引，而非在每次自动保存后强制全树重扫。

保存的强一致性规则是：`project-writer.mjs` 在 `writeMarkdownDocument()` 内部使用已取得的写后 `normalizedPath + nextMetadata` 调用 `createProjectTreeDocumentEntry()`，并将内部 `treeEntry` 与文档结果同源返回；bridge 随后 `await projectTreeCache.markMutation(project)`。二者均成功才返回 HTTP 200 与 `BridgeDocumentSavePayload`。bridge 不得重新解析路径或再次 `stat`。

缓存失效失败时，HTTP 返回 5xx，但错误体必须使用专用 `DOCUMENT_SAVED_CACHE_INVALIDATION_FAILED` 合同，携带已写入文档的 `path`、`content`、`mtimeMs`、内容 hash 和 `treeEntry`。App 不把它当作普通可重试保存失败：先以响应数据确认本地保存基线并更新当前时间索引，再显示“文件已保存，但最近索引同步失败”的可恢复状态；用户的重试动作只重试索引/树同步，不重写文档。不得静默返回 HTTP 200 或一般 `treeStatus: dirty`，否则“保存后不使用陈旧最近排序”的验收不能成立。

扫描器和写入器共同调用服务端纯函数 `createProjectTreeDocumentEntry(normalizedPath, stats)`，集中处理路径规范化、`birthtimeMs` 降级和 `recentAtMs` 计算；不得在两个路径重复实现时间规则。不得在前端为每一行单独请求文档内容或 `stat`，否则大项目会出现 N+1 请求和排序闪跳。

### 前端：原始树与最近投影分离

`App.tsx` 继续维护按手动顺序构建的原始 `fileTree`，供普通树、收藏、展开状态和路径操作使用。最近视图是渲染投影，不改写 `fileTree`、`manualNodeOrderByParent`、`expandedFileNodes` 或 Profile 数据。

时间索引以 `Map<path, ProjectTreeDocumentEntry>` 或等价不可变结构留在 App 状态中，并只由 `ProjectTreeSnapshot` 水合、刷新及保存响应增量更新。快照和保存响应写入必须同时满足当前 `projectId`、`profileId` 与 `workspaceLoadRevision`；每次项目或 Profile 切换都必须在发起异步加载前递增该 revision。切换项目/Profile、清空工作区或请求失效时同步清空时间索引与 `showRecentOnly`。最近投影只依赖：原始文件树、时间索引、`hiddenPaths`、`showRecentOnly`；搜索仍由 `WorkspaceLayout` 在该投影后处理。

创建、复制、移动、重命名、删除等节点 mutation 响应继续只表示操作已完成与树已失效，绝不携带部分 snapshot。每个成功调用点必须随后调用 `getProjectTreeSnapshot()`，并在同一状态提交中替换 `fileTree` 与时间索引；不得用节点响应单独更新其中之一。

最近行新增展示层字段或 `showRecentOnly` 渲染标志：文件名仍是稳定的可访问名称，项目相对路径作为仅视觉的副标题（`aria-hidden`）。这样既满足同名文件辨别，又不无意改变既有文件按钮的辅助技术名称和测试选择器。

## 实施设计

### 阶段一：跨平台时间合同与树缓存

涉及：`server/project-scanner.mjs`、`server/project-tree-cache.mjs`、`server/bridge-server.mjs`、`src/workspace/local-bridge-access.ts`、`src/workspace/workspace-provider.ts`，以及相应 server/workspace 测试。

1. 抽取 `createProjectTreeDocumentEntry(normalizedPath, stats)`，由扫描器和 writer 的写后 `stat` 共用；将扫描返回值从路径数组提升为 `ProjectTreeSnapshot.entries`，并保留内容根、Markdown 扩展名、目录跳过和路径规范化规则。
2. 为每个条目计算跨平台时间字段和可检测的 mtime 降级值；测试中显式模拟非有限或负值 `birthtimeMs`。
3. 定义 `canonicalizeTreeEntries()`：校验相对 Markdown 路径、有限时间字段，并重算/校验 `recentAtMs = max(createdAtMs, modifiedAtMs)`；按 `path ASC` 输出。相同路径的重复条目只有时间字段完全一致时才能去重；不一致则拒绝该 snapshot 并重新扫描/报错。提升树缓存快照版本，令完整 canonical entries 而非仅路径进入 snapshot revision。旧快照自动失效并重建。
4. 将 bridge ready/wait 响应、access 层轮询、provider 和 App 类型改为单一 `ProjectTreeSnapshot`；删除 paths-only 公共方法，所有调用方从同一快照派生路径数组，避免新增第二次扫描或保留陈旧索引。
5. `project-writer.mjs` 在写后以现有 `nextMetadata` 创建并返回内部 `treeEntry`；`POST /document` 仅封装该条目，成功 `await projectTreeCache.markMutation(project)` 后返回 `BridgeDocumentSavePayload`。缓存失效失败返回 `DOCUMENT_SAVED_CACHE_INVALIDATION_FAILED` 5xx 及完整保存基线，App 仅在当前 project/profile/revision 仍匹配时应用它，并只重试索引同步。不得以每次自动保存触发强制全树刷新或重写文档作为默认实现。
6. 节点 mutation 成功后，统一通过 `getProjectTreeSnapshot()` 回读并原子替换文件树和时间索引；迁移所有现有 paths-only 回读调用点与测试 mock。
7. 保留 `mutationEpoch` 对扫描与落盘的双重检查，并增加“写入/失效发生在扫描中”的并发用例，证明旧扫描不会覆盖或持久化新时间。

完成条件：首次加载、等待索引、强制刷新和缓存恢复都返回合法、规范化且带稳定时间字段的文档条目。

### 阶段二：严格隐藏的最近列表投影

涉及：`src/workspace/file-tree.ts`、`src/workspace/file-tree-types.ts`、`src/App.tsx`、`tests/workspace/file-tree.test.ts`。

1. 新增纯函数，从严格隐藏后的 `VisibleFileTreeNode[]` 收集文件节点，并按时间索引的 `recentAtMs DESC, path ASC` 返回扁平文件节点。
2. 时间索引缺项不能导致文档消失：使用已定义的最低优先级回退值并稳定排序，同时在测试中覆盖这种异常数据；正常扫描结果必须完整覆盖文件树。
3. 最近模式调用 `createVisibleFileTree({ showHiddenItems: false })`，普通和收藏模式继续使用当前 `showHiddenItems`。
4. 不改变输入树或节点 `meta`，保证隐藏、当前文档、收藏标记和节点操作仍能使用原始路径。

完成条件：隐藏文件、隐藏目录后代、正常文档、同时间文档与缺少索引文档均得到可预测结果。

### 阶段三：浏览模式 UI 与交互限制

涉及：`src/App.tsx`、`src/app/AppShell.tsx`、`src/app/WorkspaceLayout.tsx`、`src/index.css`、组件测试。

1. 在 `panel__favorite-toggle` 右侧添加「最近」按钮，使用独立 class、`aria-label="按最近时间查看文档"` 与 `aria-pressed`，视觉规格与收藏按钮协调。
2. 贯穿 AppShell/WorkspaceLayout 的 `showRecentOnly` 与切换回调；启用一方时关闭另一方。
3. 最近模式空状态使用“当前没有可见的最近文档”；搜索无匹配时沿用“没有匹配的文件”。
4. 让 `reorderEnabled` 同时受 `!showRecentOnly` 约束；在节点 drag start、目录 `dragover` 和目录 `drop` 入口都防御性拒绝最近模式，确保遗留或合成拖放事件也 fail-closed。
5. 最近模式保留文件选择、当前项样式、文件级收藏/隐藏按钮和右键菜单；目录专属展开、目录操作和树尾拖放不出现。
6. 最近模式为每行渲染相对路径副标题，作为 `aria-hidden` 的视觉信息；文件按钮的可访问名称保持文件名，避免破坏现有键盘与测试语义。

完成条件：按钮可键盘操作且状态明确；切换模式后内容、空状态、搜索和拖放行为符合已确认语义。

### 阶段四：刷新、保存与回归验证

涉及：现有 `tests/server/*tree*`、`tests/workspace/*bridge*`、`tests/workspace/file-tree.test.ts`、`tests/app/workspace-layout.test.tsx`、`tests/app/app-session-restore.test.tsx`，按实际模块补充。

覆盖至少包括：

- 最新修改文档排在创建较早但未修改的文档之前；
- tree cache 冷启动、持久化恢复、旧 version 失效、ready/wait 快照响应、access 轮询与 provider 透传均不丢失 entries；
- 新创建文档进入列表；保存后服务端缓存失效、`BridgeDocumentSavePayload.treeEntry` 即时更新索引并刷新排序；缓存失效失败以专用错误确认保存基线且仅重试索引同步，不产生二次写入冲突；显式刷新后外部修改可见；
- 强制扫描与保存/`markMutation()` 交错时，旧扫描不会覆盖内存快照或落盘，最终 entries 含写后 `recentAtMs`；
- `birthtimeMs` 不可靠时 mtime 降级；不同平台格式的相对路径仍正确；
- 隐藏单文档、隐藏目录、隐藏目录后代在最近模式始终不可见；
- 正常树显示隐藏项时，最近模式仍不泄露隐藏项；
- 收藏/最近互斥、二次点击恢复普通树、切 Profile 后会话态复位；每次 Profile 切换先递增 revision，A→B→A 的迟到响应也不得把旧快照/保存响应写入新索引；
- 创建、复制、移动、重命名、删除后只通过 snapshot 回读原子更新文件树与时间索引；
- 搜索作用于最近的扁平可见集合；同名路径可辨别；
- 最近模式下拖拽重排和目录拖放被拒绝，普通模式无回归。

完成条件：定向测试、`npm run build` 与 `git diff --check` 通过；若全量 lint 存在既有失败，需单独记录且不得归因于本功能。

## 验收清单

- [ ] 收藏按钮右侧存在可访问的「最近」按钮，并正确反映 pressed 状态。
- [ ] 收藏与最近互斥；再次点击当前模式回到普通树。
- [ ] 最近列表不显示目录层级，按 `max(创建时间, 修改时间)` 从新到旧排序。
- [ ] 同一时间的顺序稳定；同名文档可凭视觉相对路径区分，且文件按钮可访问名称保持稳定。
- [ ] 缺失或不可靠创建时间时，在 Windows、macOS、Linux 与网络/同步目录上均可回退到修改时间。
- [ ] 隐藏文档、隐藏文件夹及后代，即使开启“显示隐藏项”也绝不出现在最近列表。
- [ ] 搜索能筛选最近列表，不改变源文件树或手动排序。
- [ ] 保存后仅在缓存失效成功时返回成功，并立即用 `treeEntry` 更新当前文档的最近排序；缓存失效失败能确认已写入基线并仅重试索引同步；创建、外部刷新、重命名、移动和删除后，最近列表不会保留陈旧条目或时间。
- [ ] 最近模式下不能拖拽排序或拖放移动；普通和收藏视图不回归。
- [ ] Profile 切换不串用浏览模式或隐藏规则。

## 风险与控制

1. **将 `birthtime` 误当内容修订历史**：文档和 UI 文案统一使用“创建/修改时间”，不使用“版本”或“修订记录”；以 mtime 降级并在方案中明确边界。
2. **缓存继续只按路径判定**：缓存 canonical/revision 必须包含元数据，否则外部修改后可能路径未变却排序陈旧。
3. **隐藏泄露**：最近投影必须从严格隐藏树生成，不能先展平原始路径再只剔除精确隐藏项，否则会漏掉隐藏目录的后代。
4. **为每篇文档发请求**：所有排序时间来自一次树扫描响应，禁止前端逐项读取文档元数据。
5. **破坏手动排序与拖放**：最近仅是渲染投影；在 UI 和事件处理两处禁止重排，不写回任何排序 state。
6. **平台锁定**：只使用 Node.js 标准跨平台文件 API，所有路径保持项目相对、POSIX 分隔符；测试不得断言 Windows 专属时间或路径行为。
7. **缓存失效失败后的写入歧义**：本轮选择强一致性，保存请求返回失败而文件可能已经写入；专用错误必须带回保存基线，前端只重试索引同步，不能把相同内容再写一次，测试覆盖此分支。
