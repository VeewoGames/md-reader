## 审查结论

**可采用修订后的计划，获得实施授权后先执行第一章检查点。** 五章、20 个原子任务的拆分足以接手，无需继续细拆到按钮或转发函数。独立架构代理检查合同、owner、依赖及源码反证；独立 recheck reviewer 按优雅性专项检查必要性、直接性、复用、状态和验证表面，并对合入修订作了第二次只读复核。主代理综合发现后修订计划，未修改代码或主方案。

检查点不等于已有正确结论：同一 runtimeHome 的 writer 是否全受独占保护、路径大小写是否产生身份碰撞，仍须取证。计划明确未展开受它们影响的锁与迁移分支，不能跳过门禁直接运行后续共通任务。

## 需求与架构依据状态

需求已明确：当前 Profile 可添加、持久化自由排序、只注销项目登记、直接移除当前项目并安全切换、最后清空。ADR 0022 的本机 registry／项目配置分层和 ADR 0023 的无 active 保留 Profile 是架构依据。

计划不新增产品规则，不改变 registry 唯一 owner。App 管理当前呈现工作区，服务端保存登记 active；两者通过快照、版本与既有 prepare／commit 协作，不能在多窗口场景中把本地呈现身份当作服务端事实。

## 复用与精简评估

- **任务粒度：** 排序与移除合在一个 registry 业务结果中，管理面板与共享添加入口合在一个可操作结果中，合理；不为数量拆分每个按钮、HTTP 包装或测试断言。
- **数据模型：** 沿用 projects 数组作为顺序和 revision 作为并发版本；initialized 派生，协调只用最小占位，不引入排序表、移除历史或独立版本库。
- **动作模型：** 复用现有保存对话框、prepare、commit、工作区代次和草稿。一个清单操作在途、一个待确认记录足以覆盖现有失败场景；不增加通用事务引擎、事件总线或恢复存储。
- **组件复用：** 两处添加共用输入对话框；拖动与上下移共用 reorder；通用选择器不变成项目管理平台。不默认引入拖动库。
- **验证归属：** registry 测业务组合，HTTP 测路由与错误，provider／客户端测边界合同，App 测会话与草稿，组件测输入与排列，真实浏览器测指针体验。第五章复用定向结果，只补集成影响，避免同样排列组合逐层重复。

## 必要复杂度

| 保留结构 | 删除后失去的保证 |
|---|---|
| writer／身份事实门禁 | 锁或迁移路线会建立在未经验证的假设上 |
| 完整文件事务与 Profile CAS | 分别出现跨 Profile 丢写和旧客户端覆盖；二者不能互相替代 |
| dirty gate → prepare → registry commit → UI commit | 无法同时保护草稿、邻项可用性、active 引用和当前呈现身份 |
| reconcile 与待确认记录 | 一次 GET 可能早于原 POST，无法保证确认后旧命令不会再落盘 |
| 显式空态、URL 清理、initialized | 最后清空可能残留旧工作区，或再次切换 Profile 时把项目自动接回 |
| 独立真实交互验收 | 组件测试不能证明真实鼠标拖动、滚动、取消与误触切换行为 |

这些结构各自映射到已确认需求或已知失败路径。精简应集中在重复状态、临时协调器和镜像测试，不能通过取消当前移除或最后清空来降低复杂度。

## 风险与缺口

- **实施前必须解决：** 多 writer 约束及大小写敏感路径身份。按第一章证据收敛，需要改变架构或迁移时再补相应任务与决定；不在本轮承诺某个锁策略或修改 ID。
- **实施后必须验证：** 平台安全替换、CAS fence 时序、外部移除与旧草稿、刷新重启、真实鼠标排序。计划覆盖不代表已经通过。
- **接手时重查：** 工作区已有服务相关修改，相关文件可能与后续 writer 检查重叠。应按路径和 diff 精确协作，不归入本任务提交或清理。
