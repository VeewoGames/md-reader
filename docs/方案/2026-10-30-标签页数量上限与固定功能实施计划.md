# 标签页数量上限与固定功能实施计划

## 计划概述

目标是按[功能方案](2026-10-30-标签页数量上限与固定功能方案.md)交付可持久化的未固定标签上限、自动淘汰及标签固定。上限默认 10，范围 1–30；固定不计入上限，刷新保留，手动关闭后重新打开不再固定。按打开先后选择安全候选，优先保留活动标签；已有草稿、未完成保存、失败或冲突的标签不自动关闭。降低上限、取消固定及恢复超额会话不立即裁剪，下次打开新标签时再处理。

顺序为：①建立兼容的数据与可靠的会话写入；②统一所有打开入口与安全淘汰；③接入设置和图钉；④综合验证及更新产品文档。每章产出独立可验证结果，后章依赖前章。此计划是实施提案，须经用户批准后执行；既有工作区大量未提交变更必须保留，不自动提交或推送。

## 第 1 章：状态模型与恢复

**目标和范围**：为配置、固定状态和打开先后建立唯一会话模型与持久化路径，旧数据可恢复；不改变用户现有文档内容。**依赖**：确认当前工作区状态及既有项目/profile 切换行为。**成果**：可读写的新旧状态和顺序正确的恢复模型。**完成条件**：相关单元及恢复测试通过，未引入旧写覆盖新会话。**衔接**：为第 2 章提供可靠的状态和写入合同。

### 1.1 子计划：配置与会话数据

输入：`src/workspace/profile-store.ts`、`server/project-profiles.mjs`、`src/workspace/local-state.ts`、`src/workspace/workspace-session.ts`。输出：经归一化的上限和会话标签元数据。非范围：UI。风险：旧 profile 和会话缺字段、异常字段导致恢复失败。

- **1.1.1 配置合同**：在浏览器与服务端 profile 默认和归一化路径增加整数上限，旧数据默认 10，异常值按 1–30 合理归一化；保证本地和服务端保存读取一致；将当前应用内同项目/profile 的 profile 读改写统一协调，避免滑条与布局、导航等设置交错覆盖。跨进程并发控制不纳入本轮承诺。验证 `tests/workspace/profile-store.test.ts`、`tests/server/project-profiles.test.ts` 的旧值、上下界、往返及滑条与布局/导航交错保存测试；失败先修复归一化，不覆盖已有 profile。
- **1.1.2 标签元数据**：会话记录每个打开标签的固定状态和独立打开先后序列；以路径作为当前项目内关联，关闭时清除固定和序列，重开生成新顺序。旧会话以保存的显示顺序初始化先后，默认未固定；去重并处理缺失或无效条目。验证 `tests/workspace/local-state.test.ts` 和会话模型测试；失败保留原始状态并修正迁移逻辑。
- **1.1.3 恢复和路径变更**：覆盖 `App.tsx` 两层归一化和两条恢复路径，文件重命名、移动、删除及缺失文件自愈时同步迁移或清理元数据；刷新与项目/profile 切换相互隔离，恢复超额不主动裁剪。恢复加载绑定标签打开生命周期、请求版本和草稿修订；返回时核验标签仍存在、未被替换且草稿未变，过期结果不得重建标签、覆盖草稿、改变活动项或重置当前编辑器状态。增加受控延迟下的关闭、重开、切换和输入回归。验证 `tests/app/app-session-restore.test.tsx` 及相关路径变更测试；不匹配时停止后续 UI 接入。

### 1.2 子计划：会话快照写入顺序

输入：`App.tsx` 中全部 `localStateStore.saveState` 调用、`src/workspace/local-state.ts`。输出：按项目/profile 隔离、以最新会话投影标签字段的有序写入合同。非范围：跨浏览器多客户端协作。风险：滚动、模式、打开、重排或关闭的异步整对象写互相覆盖。

- **1.2.1 盘点并收敛写入**：逐条识别会话写入口和生命周期，在单一协调入口内按项目/profile 串行读改写并从最新有效会话投影标签字段；项目切换后旧任务不得投影新会话。允许采用经测试证明等价的版本控制实现，但不得仅序列化打开操作。验证受控延迟交错下重排、固定、关闭、滚动和切换均不复活旧标签或丢失字段；失败时停止并修复，不以增加重试掩盖覆盖。
- **1.2.2 失败反馈**：写入失败保留当前运行时状态并可见提示，后续操作不得宣称持久化成功；明确刷新后的结果取决于最后成功快照。通过注入失败和后续成功测试验证；失败不静默吞错。

## 第 2 章：统一打开与安全淘汰

**目标和范围**：所有新标签入口遵守同一容量策略，保留既有自动保存合同及草稿。**依赖**：第 1 章。**成果**：可验证的候选选择、打开/关闭和失败行为。**完成条件**：所有打开入口及并发/失败回归通过。**衔接**：第 3 章消费固定状态及配置。

### 2.1 子计划：容量策略

输入：`WorkspaceSession`、保存状态和 IME 输入状态。输出：不修改状态的候选选择与结果。非范围：图钉显示。风险：活动标签、未提交输入或并发操作造成误关闭。

- **2.1.1 安全候选选择**：未固定计数为 N、上限 L 时，新开需淘汰 `max(0, N + 1 - L)` 个；按打开顺序先选非活动安全标签，数量不足时再考虑安全的活动标签。安全判定同时检查草稿与已保存内容、保存状态以及尚未提交的输入/IME 状态；固定标签绝不参与。验证正常、超额、活动优先保护、所有保存状态和候选不足；不足时整个选择失败，不部分关闭。
- **2.1.2 统一打开事务**：核对并接入文件树选择、新建文档、文档链接、深链和加载成功/失败等真实入口；已打开目标直接切换，保留其草稿。新目标先读取，提交前基于最新会话、项目/profile 和输入状态重新校验候选；仅在读取及校验成功后一次性提交淘汰与打开。过期请求不得改变新上下文；读取失败保持原标签，已创建文件若打开失败要准确提示文件已创建。用 `tests/app/app-autosave.test.tsx`、链接及会话测试覆盖脏目标、失败、快速打开和切换；若无法保证状态安全，暂停并调整设计。
- **2.1.3 手动关闭与持久化**：复用原有手动脏稿确认和活动标签回退；自动淘汰使用统一策略而非绕过安全检查直接关闭。一次提交后持久化最终顺序、活动标签、固定及打开顺序，验证关闭/重开、拖拽与刷新；失败保留可见错误并按 1.2.2 处理。

## 第 3 章：选项和标签交互

**目标和范围**：让用户调整上限与固定标签，保持现有标签切换、关闭和拖拽体验。**依赖**：第 1、2 章。**成果**：可访问的设置与图钉。**完成条件**：组件和交互验证通过。**衔接**：第 4 章进行整体验收。

### 3.1 子计划：滑条和图钉

输入：`src/app/TopBar.tsx`、`src/app/AppShell.tsx`、`src/App.tsx`、`src/index.css`。输出：设置和固定操作。非范围：标签收藏与手动排序规则变更。风险：指针事件与拖拽、关闭冲突；触屏无法悬停。

- **3.1.1 上限滑条**：在现有右上角阅读选项加入 1–30 整数滑条及当前值；切换项目/profile 恢复对应设置。调整只保存上限，不立即关闭标签；处理 profile 保存失败并恢复或提示真实状态。验证 `tests/app/topbar-reading-preferences.test.tsx`、profile 回归及保存失败。
- **3.1.2 固定交互**：未固定标签悬停满 1 秒显示左侧图钉，移出取消计时；固定标签图钉持续可见。按钮支持键盘聚焦及明确无障碍名称；在不支持悬停的粗指针设备直接显示图钉，用户点击即可固定或取消；避免点击触发标签切换、关闭或拖拽。验证计时、取消、固定/取消、焦点、触屏直接点击图钉及与现有拖拽共存；失败时修复交互，不以禁用拖拽解决。

## 第 4 章：综合验证与交付

**目标和范围**：证明规则、恢复和界面在真实组合下协同；更新产品文档。**依赖**：第 1–3 章。**成果**：验证记录和准确的产品说明。**完成条件**：自动检查通过，人工验收结果明确；失败或未做的项目如实记录。**衔接**：交由用户验收，不自动提交或推送。

### 4.1 子计划：回归与验收

输入：前述变更和现有测试集。输出：检查结果和产品文档。非范围：清理既有脏工作区。风险：自动化通过但真实浏览器手感或触屏交互未验证。

- **4.1.1 自动检查**：运行相关 Vitest 测试，并按实际改动运行 `npm test`、`npm run build` 和 `npm run lint`；记录命令及通过/失败原因，区分既有问题。关键覆盖还包括旧会话、缺失文件、路径变更、跨项目/profile 隔离、加载失败、未保存保护、保存中、冲突和连续操作。失败则修复或明确阻塞，不宣称通过。
- **4.1.2 实际交互验收**：在可运行环境验证设置保存恢复、1 秒悬停、图钉固定及手动关闭、拖拽后淘汰、降低上限延迟处理、无安全候选及触屏/键盘路径；分别记录真实体验与自动化证据。环境不具备时标为未验收。
- **4.1.3 文档与交付**：按实际实现更新 `docs/04_工作区与交互.md` 等相关现行产品文档，保留已有未提交改动；总结行为、验证、剩余限制。检查最终 diff，只报告本任务变更，不自动提交或推送。

**复核记录**：已对需求、代码边界和执行步骤进行独立只读复核；补充恢复加载的标签生命周期与草稿修订校验，以及触屏图钉直接可见的验收路径。尚未运行程序或测试，执行前仍须检查当前工作区。
