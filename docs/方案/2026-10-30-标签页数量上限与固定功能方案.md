# 标签页数量上限与固定功能方案

## 方案概述

目标是在右上角现有“阅读选项”中设置未固定标签页的数量上限，并提供标签固定功能。打开新标签达到上限时，自动关闭符合安全条件的最早打开的未固定标签；固定标签不计入上限，也不会被自动关闭。鼠标在标签上悬停 1 秒后，在左侧显示可点击的图钉。

本方案先定义标签容量与草稿保护，再规定固定、持久化和交互，最后列出实施切片和验收。产品规则已确认，实施步骤另见《2026-10-30-标签页数量上限与固定功能实施计划》；本文不构成代码实施授权。方案基于当前工作区，已有未提交修改，实施时应保留并重新核对。

## 问题、边界与不变量

- 上限针对当前项目和 profile 的**未固定**标签数量，不限制固定标签的数量；选择已经打开的文档只是切换，不触发淘汰，也不得重新读取覆盖其草稿；文档链接路径当前存在覆盖目标草稿的风险（`src/App.tsx:2418`），须纳入修正与验证。
- 用户已确认：未保存修改、保存失败或冲突的标签不能自动关闭，按顺序寻找下一个安全候选。应将正在输入、排队保存、后台保存等未完成状态也视为不可安全淘汰，直至确认保存完成。
- 当没有足够的安全候选时，保留原标签及草稿，停止产生超额的新标签并明确告知用户；不得静默丢稿或声称已打开。手动关闭仍沿用已有草稿确认流程。
- 用户已确认“最早”按一次打开生命周期的先后顺序判断，切换和拖拽不改变顺序；关闭后重新打开视为新的打开。当前标签数组兼作可拖拽显示顺序，不能直接取数组首项（`src/App.tsx`：`reorderSessionTabs` 和 `handleTabReorder`）。
- 固定仅保护自动关闭；用户已确认固定状态刷新后恢复，仍可手动关闭，关闭后重新打开不再固定。固定状态仅属于当前打开会话，非文件收藏。

## 新增或改变的概念、唯一 owner 与数据流

- `WorkspaceSession` 拥有当前标签、固定状态和打开先后；`TopBar` 仅展示并发出操作。显示顺序与打开先后分开保存。现有 `WorkspaceTab` 和会话模型位于 `src/workspace/workspace-session.ts`。
- 上限建议作为当前项目、当前 profile 的配置，接入现有 profile 读取、保存与归一化链路；不是仅存组件状态。当前配置见 `src/workspace/profile-store.ts`，服务端 profile 处理也需核对是否保留新字段（`server/project-profiles.mjs`）。用户已确认滑条默认 10、范围 1–30；建议步长 1，显示具体数值。
- 固定和打开先后作为会话快照扩展现有 `WorkspaceLocalState`，按项目和 profile 隔离；与 `openDocumentPaths` 的显示顺序共同恢复（`src/workspace/local-state.ts`）。两处归一化（`src/workspace/local-state.ts` 与 `src/App.tsx`）及两条会话恢复路径均须保留新字段。旧快照无顺序时，以保存的显示顺序作为一次性近似基线，不能恢复已丢失的历史打开时间；旧标签默认未固定。失效路径清理与文件重命名、移动时须同步处理新字段（`src/workspace/document-path-mutation.ts`）。
- 在会话层统一处理所有新建标签入口，包括文件选择、创建文档及加载成功/失败路径；先判定是否为已打开标签，再决定安全候选、加载和最终提交。现有 `src/App.tsx` 的 `ensureTabExists`、`applyLoadedDocument`、`handleDocumentSelect` 和文档创建/加载路径均可能加入标签，需逐条核对，避免某条路径绕过规则。
- 对连续打开、异步加载和项目/profile 切换，操作必须基于最新会话串行化或使用等价的版本校验；恢复及普通加载都绑定标签打开生命周期、请求版本和草稿修订；返回时核验目标仍存在、未被替换且草稿未改变。过期加载结果不能重建标签、覆盖草稿或新项目状态、改变活动项或重置当前编辑器状态。所有会话相关的整对象持久化写入，包括滚动、模式、重排、关闭和路径变更，都需要统一顺序或版本控制，并从最新会话投影标签字段；仅给打开操作加队列不足以避免旧写回复活标签或覆盖固定状态。保存失败需可见提示，刷新后恢复以实际持久化结果为准。

## 推荐决策、关键理由与一个关键失败路径

1. 打开新文档时按打开先后扫描未固定标签，跳过所有不安全候选，关闭最早的安全候选；已固定标签永不自动关闭。读取成功后须重新核验候选的草稿、保存状态和输入法组合等尚未提交输入；候选关闭与新标签加入作为一次会话状态转换，保持活动标签有效。读取失败不淘汰原标签并反馈失败。创建文档若已产生文件但无法打开，应保留文件并明确告知创建和打开分别的结果。
2. 悬停满 1 秒后显示图钉；移出前取消计时。固定后建议图钉持续可见，以便识别和取消固定；键盘聚焦时也应可见并能操作，图钉按钮应有明确的固定/取消固定无障碍名称，且不误触标签切换、关闭或拖拽。触屏或其他不支持悬停的粗指针设备上，图钉直接可见，点击即可固定或取消固定，并保持拖拽与关闭入口可操作。
3. 用户已确认：下调上限或取消固定导致超额时，保留现有标签，等下次打开新的未固定标签时再处理。用户同意恢复旧会话已超额时采用相同处理方式。打开时按顺序裁剪足够数量的安全候选，以便加入新标签后符合上限；裁剪优先保留当前活动标签，其他安全候选不足时才将当前活动标签作为候选。若安全候选仍不足，保留原会话和草稿并提示，停止打开新标签。
4. 关键失败路径：上限为 3，三个未固定标签均有未保存内容，用户打开新文档。系统不能自动关闭任何一个，因此保持原会话和草稿，明确说明先保存、手动关闭或固定后再操作；固定只排除计数，并不保存草稿。对于读取新文档或状态持久化失败，也应报告真实结果，不用旧快照覆盖新的会话。
